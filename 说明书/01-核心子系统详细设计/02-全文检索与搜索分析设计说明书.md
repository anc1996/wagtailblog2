# 02-全文检索与搜索分析实现说明书

> **文档版本**：v1.1.0
> **文档定位**：全文检索与搜索分析子系统落地实现说明书（从设计方案转为工程落地实现规范，杜绝冗余讨论）
> **架构师**：gpt-5.6-sol（高推理）

## 1. 业务背景与架构演进

### 1.1 为什么退役 Wagtail 原生搜索

Wagtail 自带的搜索后端（`wagtail.search.backends.elasticsearch`）基于模型字段直接映射，存在以下核心短板：
1. **大文本混入与权限穿透**：无法应对本系统 `BlogPage.body` 大文本存放于 MongoDB、MySQL body 为空的架构。
2. **缺乏树形权限继承感知**：父目录设置“仅登录可见”或“私密加锁”时，子孙后代页面在 ES 索引中无法即时级联更新权限范围，导致越权检索。
3. **缺少深度运营分析**：原生仅有简单计数的 `search-terms`，缺少多维度时序趋势、零结果分析、占比环形图及动态时间过滤。

### 1.2 独立内容搜索引擎的目标

建立自建、轻量、高可用的独立全文检索体系：
- 采用独立内容索引（`wagtailblog-prod-content-v*`）与 Alias 读写分离。
- 基于 **MySQL Outbox 模式** 实现 100% 事务性投递，保障极端网络中断下数据不丢不漏。
- 基于 **`ContentSearchScopeJob`** 闭环解决树形隐私继承与实时下架。
- 内置企业级**搜索分析控制台**，提供直观的 KPI、图表与关键词大盘。

## 2. 核心数据结构与索引设计

### 2.1 Elasticsearch 内容索引 Mapping 契约 (v005+)

- **Alias 路由**：对外统一暴露 `wagtailblog-prod-content-read` 只读 Alias，物理索引版本切换（如 v003 -> v005）对前端无感知。
- **核心字段映射**：
  - `page_id`（integer）：MySQL 页面主键。
  - `title`（text / keyword）：标题字段，配置 `ik_max_word` 中文分词与 `ik_smart` 检索，加权权重设为最高（boost=10.0）。
  - `intro`（text）：简介纯文本，参与全文召回（boost=3.0）。
  - `body`（text）：从 MongoDB 提取并清洗后的正文语义文本，分词建立倒排索引（boost=1.0）。
  - `tags`（keyword）：标签数组，用于精确聚合与标签多选。
  - `scope_root_ids` / `view_restrictions`（keyword 数组）：用于权限过滤的父级路径与加锁标记。
  - `tombstone`（boolean）：下架/删除墓碑标记，为 `true` 时检索管道一票过滤。

### 2.2 事务性发件箱（Outbox / Delivery）投递管道

为保证跨库写入的原子性与可靠性，系统拒绝在 Web 进程同步直连 ES 写入，统一采用可靠投递流：

```text
[BlogPage 发布/修改/删除]
       │
       ▼ (同一 MySQL 事务内)
 ┌─────────────────────────────────────────────────────────────┐
 │ 1. 写入业务表                                               │
 │ 2. 写入 SearchOutboxEvent (记录事件类型与 payload 摘要)      │
 └──────────────────────┬──────────────────────────────────────┘
                        │
                        ▼ (提交后触发异步信号)
 ┌─────────────────────────────────────────────────────────────┐
 │ 3. SearchDelivery 任务入队 (maintenance 队列)              │
 │ 4. 取得租约锁 (Lease Token)，按 batch 写入 Elasticsearch   │
 │ 5. 成功后推进 Checkpoint；失败重试 (指数退避，最大重试上限)  │
 └─────────────────────────────────────────────────────────────┘
```

## 3. ContentSearchScopeJob 树形权限检索闭环

### 3.1 隐私继承的核心难题

当管理员在 Wagtail 后台将父栏目（如“内部交流资料”）设置为受限或私密时，其下成百上千篇子文章并不会触发逐篇的 `save()` 信号。若不作特殊处理，前台未登录用户搜索依然能检索到这些私密文章片段，构成严重安全越权漏洞。

### 3.2 权限闭环的实现机制

1. **信号侦听**：监听 Wagtail `PageViewRestriction` 的创建、修改与删除事件。
2. **异步范围作业入队**：派发 `ContentSearchScopeJob` 至 `maintenance` 队列，记录发生权限变动的根页面 `page_id` 与最新限制规则。
3. **批量树遍历与权限下发**：
   - 遍历以该页面为根的整颗子树（基于 Wagtail `path` 前缀匹配，毫秒级快速索引）。
   - 为整棵树生成批量的 Elasticsearch 更新脚本，在索引中原子注入或清除权限保护标记。
   - 验证闭环：父目录加锁 -> 异步任务执行 -> 未授权前台搜索即刻下架；父目录解锁 -> 重新对未登录用户恢复公开检索。

## 4. 搜索热词与搜索分析控制台大盘

在 Wagtail 管理后台集成了一体化的**搜索分析报表大盘**（归入“报告/搜索分析”菜单，彻底替代并隐藏原生 `search-terms`）。

### 4.1 核心数据聚合体系 (`SearchAnalytics`)

- 基于 `Query` 与 `QueryDailyHits` 按本地时区聚合计算：
  - **KPI 核心指标**：总搜索量、独立搜索词数、零结果词数、环比前一周期增减百分比。
  - **Top 10 热词分布环形图**（Donut Chart）：直观展现用户高频检索关注点。
  - **搜索趋势折线图**（Trend Series）：绘制近期每日搜索量的波动曲线。
  - **明细分页表格**：支持输入关键词即时筛选、页码跳转与边界保护。

### 4.2 异步局部刷新（AJAX）架构

页面划分为三大独立端点，切换时间范围（今日、最近7天、最近30天、自定义）或翻页时，仅异步拉取对应局部 JSON/HTML，彻底告别整页重载白屏：
- `/admin/reports/search-analytics/`：控制台主骨架。
- `/admin/reports/search-analytics/dashboard/`：KPI 与双图表局部更新端点。
- `/admin/reports/search-analytics/records/`：聚合明细表格局部刷新端点。

## 6. 验证与交付结论

- **严格一致性达标**：生产与测试环境运行 `search_consistency_check --strict` 均达到 `missing=0, stale=0, ahead=0, extra=0, wrong_tombstone=0` 的全绿状态。
- **权限闭环实机演练**：通过 `browser-skill` 真实模拟低权限用户在桌面与移动视口下的端到端流程，100% 验证了“父目录加锁即下架、解锁即恢复”的铁律约束。
- **毫秒级检索与零服务负担**：百万级分词倒排检索平均耗时低于 30ms，分析控制台查询全部命中关系库联合索引，无阻塞生产风险。
