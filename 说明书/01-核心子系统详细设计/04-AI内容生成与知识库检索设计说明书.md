# 04-AI内容生成与知识库检索实现说明书

> **文档版本**：v1.1.0
> **文档定位**：AI 内容生成与知识库检索子系统落地实现说明书（从设计方案转为工程落地实现规范，杜绝冗余讨论）
> **架构师**：gpt-5.6-sol（高推理）

## 1. 业务背景与架构愿景

在技术博客与知识库运营中，高质量的元数据（引人入胜的技术标题、精准的摘要简介、标准化的标签）对于 SEO、全文检索与读者转化至关重要。

本子系统通过建立独立子应用 **`content_ai`**，将现代大语言模型（LLM）能力深度集成到 Wagtail 8.0 创作流程中，实现：
1. **未发布编辑态的智能建议**：基于浏览器当前未保存的 StreamField 内存状态生成元数据建议，不触碰底层 MongoDB 正文或发布页面。
2. **多栏目提示词资产化管理**：管理员可在后台独立维护多套针对技术、公文、理论、网络等栏目的三段提示词模板（标题/简介/标签），编辑者按需选用。
3. **知识库 RAG 语义搜索与公文报告生成**（演进规划）：支持跨多个知识库栏目两阶段混合检索，自动基于事实证据生成工作简报与总结草稿。

## 2. 独立子应用 `content_ai` 架构设计

系统坚决摒弃第三方重型插件，采用轻量自研架构：

```text
[BlogPage 编辑界面 (Wagtail 8.0)]
       │
       ▼ (下拉选择提示词模板 + 点击生成)
 ┌─────────────────────────────────────────────────────────────┐
 │ 前端脚本：提取 StreamField 内存状态 (未保存)                │
 │ POST /admin/blog/ai/generate-metadata/ (带 template_id)     │
 └──────────────────────┬──────────────────────────────────────┘
                        │
                        ▼ (权限校验 require_admin_access)
 ┌─────────────────────────────────────────────────────────────┐
 │ 1. content_ai: 读取 BlogMetadataPromptTemplate (校验启用)   │
 │ 2. blog.ai_metadata: 正文归一化、脱敏与上下文截断           │
 │ 3. OpenAIResponsesClient: 调用 DeepSeek Responses API       │
 └──────────────────────┬──────────────────────────────────────┘
                        │
                        ▼ (严格 JSON Schema 校验)
 ┌─────────────────────────────────────────────────────────────┐
 │ 前端抽屉：展示标题/简介/标签预览                           │
 │ 交互回填：Draftail React 状态同步回填 intro，注入标签       │
 └─────────────────────────────────────────────────────────────┘
```

### 2.1 提示词模板模型 (`BlogMetadataPromptTemplate`)

- **数据字段**：
  - `name`：模板名称（唯一索引，例如“数据库技术教程元数据”）。
  - `description`：用途说明。
  - `title_prompt` / `intro_prompt` / `tags_prompt`：三段提示词（各限长 2,000 字符）。
  - `is_active`：是否启用（前端仅展示已启用项；不物理删除，仅置 `is_active=False` 实现软归档）。
  - `version`：版本号（保存时若检测到三段提示词变动则自动自增）。
- **权限与管理**：在 Wagtail Snippet 注册为“博客 AI 提示词”，仅限具备超级管理员或指定运维角色的用户维护，普通编辑者仅在编辑页只读拉取模板摘要。

### 2.2 上游大模型安全契约 (OpenAI / DeepSeek Responses API)

- **协议兼容性**：采用标准 OpenAI Responses API 协议，生产环境接入 DeepSeek 主上游（`AI_METADATA_MODEL=deepseek-chat`）。
- **数据保护规则**：
  - 强制开启 `store=False`，禁止外部模型保留请求正文。
  - 服务端预先执行语义清洗与截断，限制最大上下文不超过 24,000 字符。
  - 严格约束输出为 JSON Schema：`{"title": "...", "intro": "...", "tags": [...]}`。

### 2.3 Wagtail 8.0 编辑器交互与 Draftail 状态同步

- **DOM 状态提取**（`blog_editor_context.js`）：直接读取 `#body-root`、`body-N-value`，动态还原未提交的 StreamField 内存 JSON。
- **富文本简介回填难点攻坚**：针对 Draftail 受控编辑器，若仅给隐藏 input 赋值会导致界面空白。脚本调用 `window.DraftJS.ContentState` 创建内容并触发 `#id_intro.draftailEditor.onChange(...)`，完美同步 React 内部组件树。

## 4. 知识库语义搜索与工作报告生成演进方案（RAG 规划）

针对跨专栏的知识整合需求，系统规划了两阶段混合检索架构：
1. **多索引页范围规范化**：用户选择多个 BlogIndexPage 时，算法按 Wagtail `path/depth` 自动剔除祖先-后代冗余节点，避免跨目录证据重复。
2. **两阶段检索体系**：
   - 第一阶段：基于现有 Elasticsearch BM25 快速筛选 Top 100 候选文章（耗时 < 30ms，零向量开销）。
   - 第二阶段：使用轻量本地 Embedding 模型（如 BGE-M3 / gte-Qwen2）对候选 chunk 进行高精度向量重排，锁定核心证据段落。
3. **工作报告草稿导出**：基于提取的事实证据，调用大模型生成带引用角标的工作报告初稿，支持在后台提供 Markdown 预览与可编辑 Word 下载。
