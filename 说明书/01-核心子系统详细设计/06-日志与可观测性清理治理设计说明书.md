# 日志与可观测性清理治理设计说明书

> 版本：v1.1（2026-09-04）
> 状态：方案与实施计划；本版本基于本地与生产真实日志环境证据，针对“清理不干净”、孤儿文件滞留、生产 uWSGI 未纳管及 Admin 界面交互认知偏差进行了深度优化。尚未修改运行时代码，未执行任何物理日志删除或生产操作。

---

## 1. 结论摘要与演进背景

在 v1.0 方案确立的“截断保留 Inode”、“防误删运行锁文件”和“ES 异步 Outbox 隔离同步”安全基线之上，v1.1 针对用户现场遇到的“`logs/` 目录清理不干净”、“Admin 统计与终端磁盘占用不符”等痛点，对系统进行了系统性补强：

1. **孤儿轮转临时文件受控纳管**：动态识别并安全清理 `ConcurrentRotatingFileHandler` 异常崩溃或中断滞留的 `*.log.rotate.<随机串>`（实测本地高达 5.2MB）和 `*.cleanup-*` 隔离残留；
2. **生产 Web 核心日志全量覆盖**：在 `registry.py` 白名单中正式纳管生产 uWSGI 运行日志（`runtime/uwsgi.log`），消灭生产维护盲区；
3. **消除终端与后台的容量认知偏差**：在 Admin 概览明确列出并受控保护非日志资产（如 `logs/celery/celerybeat-schedule*` 占用的 3.2MB SQLite 数据库），既确保关键调度状态不被误清，又使后台统计与终端 `du -sh` 口径保持透明一致；
4. **Admin 界面交互与信息透明度升级**：
   - 增加**“孤儿轮转文件与未纳管告警”**提示徽章与一键清理快捷入口；
   - 增加**“按文件层级下钻查看明细”**，支持查看具体每个轮转/孤儿文件占用并支持单文件受控清理；
   - 优化清理成果展示，明确区分“本次截断释放字节数”与“清理后活跃进程立即产生的新增日志”，消除视觉感知错觉；
5. **引入 Celery Beat 周期性自动生命周期清理**：在手动 Admin 清理之外，提供可选的后台自动任务，定期巡检清理过期轮转与陈旧孤儿文件，生成系统审计；
6. **ES 异步解耦与 ILM 边界保持不变**：孤儿文件因文件名随机且未被 Filebeat 采集，不在 ES 侧执行危险的宽泛 `delete_by_query`，依赖本地删除及 ES 按天滚动与 ILM 策略回收。

## 2. 背景与现状证据

### 2.1 本地与生产真实环境实地排查证据

通过对 Windows 工作区、WSL2 测试环境以及生产服务器（`192.168.20.2`）真实 `logs/` 目录的深入扫描，核实以下事实：

- **孤儿轮转文件真实滞留**：
  - 本地 `logs/celery/celery_beat.log.rotate.291108911866439907` 占用 **5.24 MB**；
  - 本地 `logs/blog/blog.log.rotate.22268440538200487` 占用 0 B；
  - 源码 `cleanup.py` 和 `services.py` 内部仅硬编码循环 `range(1, spec.backup_count + 1)`，导致这些临时轮转文件成为永久黑洞，无论在 Admin 点击多少次清理都不会被触碰。
- **生产 uWSGI 日志处于未纳管状态**：
  - 生产服务器真实存在 `logs/runtime/uwsgi.log`，但当前 `registry.py` 的白名单仅注册了 `runtime/runserver.log`（开发服务器），导致生产核心 Web 日志在后台完全不可见、无法统计、无法截断。
- **非日志调度状态数据库混入日志目录**：
  - 生产服务器 `logs/celery/` 包含 `celerybeat-schedule`、`celerybeat-schedule-shm` 以及 **3.2 MB** 的 `celerybeat-schedule-wal`；
  - 终端 `du -sh logs/celery` 统计为 8.4 MB，但 Admin 页面仅报告约 5 MB，管理员清理后终端看依然有 3+ MB，造成“后台清理无效”的误解。
- **活跃进程“截断即写”引发的认知偏差**：
  - 运行中的 uWSGI 与 Celery Worker/Beat 保持着高频写入；
  - 执行 `os.ftruncate(fd, 0)` 瞬间文件确实已归零，但不到 1 秒新日志流入，文件大小变为数百字节；Admin 界面缺乏即时解释文案，易被误解为清理失败。

### 2.2 当前代码已具备的安全底线

- `registry.py` 提供了统一的白名单机制，严格防范越界路径与未知注入；
- `cleanup.py` 对当前活跃文件使用 `os.ftruncate(fd, 0)` 保留文件描述符 Inode，保证活跃写句柄不损坏；对已知历史轮转使用原子改名隔离（quarantine）后安全删除；
- 具备签名防篡改令牌（Preview Token）与 UUID 幂等键防重机制；
- ES 同步基于 MySQL Outbox 与 `LogIndexSyncJob` 异步执行，不阻塞 Web 主线程，ES 宕机不阻碍本地磁盘释放。

## 3. 纳管与保护边界矩阵

| 目标对象 | Admin 是否纳管 | 推荐操作 | ES 处理边界 | 安全约束与保护条件 |
|---|---|---|---|---|
| **当前活跃 `*.log`** | 是 | 原地截断 `ftruncate(0)`，保留 Inode | 按设备号/Inode/截断前 offset 异步删除 | 必须来自注册表路径；严禁 unlink |
| **已知轮转 `*.log.1`~`*.log.N`** | 是 | 安全改名隔离后 `unlink` | 按 `source_key/source_path/rotation` 异步删除 | 仅允许备份上限（backup_count）内文件 |
| **孤儿轮转 `*.log.rotate.*`** | 是（归入 rotated/orphan） | 稳定时间窗后安全 `unlink` | **不构造 ES 模糊删除**，依赖本地清理与 ES ILM | 必须匹配注册文件名主干；普通文件；产生时间必须超过安全保护时间窗（默认 60s） |
| **隔离残留 `*.cleanup-*`** | 是（归入 orphan 清理） | 检查未被占用后安全 `unlink` | 不处理 | 清理中断异常残留，产生超过 5 分钟后允许回收 |
| **生产 `runtime/uwsgi.log`** | 是（v1.1 新增纳管） | 原地截断 `ftruncate(0)` | 仅当启用 ES 采集时处理 | 需正式补录进 `registry.py` |
| **运行锁 `.__*.lock`** | 否（绝对保护） | **保留，禁止触碰** | 不处理 | `ConcurrentRotatingFileHandler` 互斥锁，删除会诱发并发死锁 |
| **调度数据库 `celerybeat-schedule*`** | 否（受控保护展示） | **严格保留，禁止删除** | 不处理 | Celery Beat 持久化状态，删除会导致周期调度混乱；Admin 显式标明其大小与用途 |
| **符号链接 / 设备文件 / 目录越界** | 否（绝对防御） | **拒绝并记录审计** | 不处理 | 底层通过 `lstat` 与父目录规范化阻断路径穿越 |

## 4. 目标与非目标

### 4.1 目标

1. **彻底解决磁盘死角**：在日志 Admin 概览与清理中，动态扫描并清理与白名单关联的孤儿轮转文件（`.rotate.*`）及异常残留（`.cleanup-*`），释放被无辜占用的磁盘（如现存 5.2MB 的 celery 孤儿文件）；
2. **生产日志无缝接入**：将生产 `runtime/uwsgi.log` 纳管至注册表与 Admin 体系；
3. **消除容量不对称误解**：在 Admin 界面直观标注 `celerybeat-schedule*` 为“非日志受保护资产”，使后台统计数据与系统 `du/ls` 命令对齐；
4. **提升 Admin 交互体验**：提供孤儿文件告警徽章、支持文件明细展开查看与单文件受控清理，清晰提示“截断已成功，后续日志为新写入”；
5. **自动化保障**：提供 Celery Beat 周期性日志生命周期清理机制，避免完全依赖人工维护；
6. **保持既有安全底线**：继续执行 Inode 保护、原子隔离、ES 异步解耦与操作审计。

### 4.2 非目标

- 不删除或修改任何 MongoDB 正文、草稿快照、Wagtail Page 模型或业务数据库记录；
- 不将锁文件（`.__*.lock`）或调度数据库（`celerybeat-schedule*`）纳入可删除范围；
- 不在 Web 请求中阻塞等待 Elasticsearch，不增加即时同步 ES 复选框；
- 不针对孤儿轮转文件的随机后缀去猜测、构造宽泛模糊的 ES `delete_by_query`，避免误删有效日志；
- 不修改系统级配置（Nginx、Docker、uWSGI 核心参数）。

## 5. 详细架构设计

### 5.1 本地孤儿轮转文件动态发现与安全校验引擎

在 `wagtailblog3/apps/observability/cleanup.py` 中新增受控发现函数 `discover_orphan_rotations(spec: LogFileSpec)`：

```python
import re
import os
import stat
import time
from pathlib import Path
from django.conf import settings

# 精确匹配与 spec 关联的孤儿轮转文件及隔离残留
# 例如: celery_beat.log.rotate.291108911866439907 或 .celery_beat.log.cleanup-uuid
ORPHAN_ROTATE_PATTERN = re.compile(r"^(.+)\.rotate\.[0-9a-zA-Z]+$")
ORPHAN_CLEANUP_PATTERN = re.compile(r"^\.(.+)\.cleanup-[0-9a-fA-F]{32}$")

SAFE_ORPHAN_AGE_SECONDS = 60  # 孤儿文件写保护时间窗: 产生至少 60 秒以上才可被清理
```

#### 安全校验规则：
1. **作用域受限**：仅遍历 `Path(settings.LOG_DIR) / spec.relative_path` 所在的绝对父目录，严禁整库递归扫描；
2. **精确主干绑定**：文件名必须以 `Path(spec.relative_path).name` 为前缀，且匹配上述正则，严禁匹配其他未知文件；
3. **时间窗写保护**：调用 `os.lstat` 读取 `st_mtime`，当前时间减去修改时间小于 `SAFE_ORPHAN_AGE_SECONDS` 的文件视为“可能正在发生并发轮转”，状态标记为 `active_writing_skip`，禁止删除；
4. **类型强校验**：必须通过 `stat.S_ISREG` 确认是普通文件，若是符号链接、目录或 FIFO 立即抛出安全拒绝；
5. **双重 Inode 校验**：执行 `_unlink_rotation` 时，先改名隔离再校验设备号与 Inode，防止与新产生的文件产生竞态。

### 5.2 日志注册表增强与生产 Web 日志纳管

在 `wagtailblog3/apps/observability/registry.py` 中补充生产 uWSGI 注册项：

```python
# wagtailblog3/apps/observability/registry.py
LogFileSpec(
    key="runtime_uwsgi",
    handler="runtime_uwsgi_file",
    domain="runtime",
    kind="activity",
    relative_path="runtime/uwsgi.log",
    label="uWSGI 生产应用服务日志",
    backup_count=5,
    max_bytes=DEFAULT_MAX_BYTES,
    business=False,
)
```

- **遗留非标日志处理原则**：针对历史产生的非标日志（如 `error_legacy_before_observability_20260729.log`），不在代码中写死偶发文件名，而是在文档中提供受控清理指引，或由超级管理员确认后通过运维单次归档。

### 5.3 Admin 界面与 UX 优化设计

#### 1. 概览页（`overview.html`）提示徽章与非日志资产说明
- **孤儿轮转告警横幅**：当全盘扫描发现存在稳定时间窗外的孤儿轮转文件时，在概览顶部展示提示条：

  > ℹ️ Celery 调度数据库（`celerybeat-schedule` 等，占用 3.2 MB）受安全策略保护，不纳入日志清理。

#### 2. 文件明细下钻视图（File Detail Drawer）
- 在模块行增加“展开文件明细”下拉折叠区，清晰展示：
  - 当前文件（如 `celery_beat.log` - 197 KB）
  - 固定轮转（如 `celery_beat.log.1` - 0 B）
  - 孤儿轮转（如 `celery_beat.log.rotate.29110...` - 5.24 MB [标记为可清理]）
  - 提供单文件定向清理按钮，满足精确治理需求。

#### 3. 清理结果与审计反馈明细
- 清理成功后，页面与 `LogClearAudit` 详细报告：
  - 截断当前文件：X 个（已释放 Y KB）；
  - 删除固定轮转：M 个（已释放 N KB）；
  - 删除孤儿轮转：K 个（已释放 5.24 MB）；
  - 提示信息：“当前文件已成功截断至 0 字节。由于服务持续运行，后台进程已实时写入最新日志（当前大小：0.4 KB）。”

### 5.4 Elasticsearch 异步 Outbox 同步与 ILM 策略

1. **孤儿文件不构造 ES 删除计划**：孤儿文件因文件名随机且未被 Filebeat 采集，v1.1 明确规定：本地删除后，该文件对应审计标记为 `index_sync_state = not_required`，避免向 ES 发起危险模糊匹配；
2. **保留原有 Outbox 异步同步**：当前文件与固定 `.N` 文件清理后，继续沿用 `LogIndexSyncJob` 投递至 `maintenance` 队列，由 Celery Worker 异步执行精确范围删除与补偿重试；
3. **长期保留依托 ILM**：ES 历史日志的最终空间释放依托索引生命周期管理（ILM 按天滚动删除整索引），禁止在 Web 端使用高频全量 `delete_by_query`。

---

### 5.5 Celery Beat 周期性自动生命周期清理（阶段 E）

新增定时运维任务 `wagtailblog3.apps.observability.tasks.cleanup_expired_logs_task`：
- **执行周期**：每周日凌晨 03:00（或每日通过 settings 配置）；
- **执行内容**：
  - 自动清理产生超过 24 小时的孤儿轮转文件（`.rotate.*` 和 `.cleanup-*`）；
  - 自动清理修改时间超过最大保留天数（例如默认 30 天）的历史轮转 `.N` 文件；
  - 记录审计日志，操作用户标记为 `system_celery_beat`，来源 IP 标记为 `127.0.0.1 (cron)`；
- **配置开关**：`OBSERVABILITY_AUTO_CLEANUP_ENABLED = False`（默认保守关闭，需显式开启）。

## 8. 数据、服务与安全影响

- **数据库影响**：无 Schema 变动，无需执行 Django `makemigrations`；
- **本地磁盘影响**：安全释放滞留的孤儿轮转文件（立即回收 5.2MB+ 空间）；当前日志保持 Inode 不变；
- **服务影响**：无需重启任何系统底层依赖；仅在修改 Celery 任务后按规范重启 `maintenance` Worker 和 Beat；
- **安全保障**：全流程基于白名单与安全断言，防止路径穿越；操作留存不可篡改的 `LogClearAudit` 台账。
