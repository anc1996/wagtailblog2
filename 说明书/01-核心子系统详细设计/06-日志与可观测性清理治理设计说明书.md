## 1. 业务背景与治理目标

在企业级 Wagtail 系统运行中，日志高频写入易引发磁盘膨胀，而传统的暴力清理极易引发进程锁死、Inode 句柄失效及误删关键数据。针对现场实测发现的“孤儿轮转文件滞留”、“生产 uWSGI 日志未纳管”、“调度数据库混入日志目录”以及“历史审计台账无限膨胀”四大痛点，本系统构建了一套**安全截断、孤儿纳管、终态归档与全流程可观测**的日志治理体系。

### 核心架构原则
1. **原地截断保留 Inode**：对运行中进程的活跃日志采用 `os.ftruncate(fd, 0)`，坚决杜绝 `unlink`，确保活跃写句柄不损坏；
2. **动态孤儿轮转受控清理**：动态识别并安全清理异常崩溃滞留的 `*.log.rotate.*` 与 `*.cleanup-*` 隔离残留，释放隐蔽磁盘空间；
3. **资产白名单与绝对保护边界**：严格区分日志与受保护非日志资产（调度数据库 `celerybeat-schedule*`、进程互斥锁 `.__*.lock` 绝对禁止删除）；
4. **180 天生命周期终态归档**：审计历史台账仅保留 180 天，清理前执行 JSON 压缩冷备份，并通过“终态保护门禁”防止级联删除未决 Outbox 任务；
5. **Outbox 事务解耦与异步同步**：审计与清理结果强事务记录于 MySQL，ES 索引同步由 Celery 异步消费，Web 响应零阻塞。

## 2. 资产纳管与安全保护边界矩阵

系统建立底层文件白名单校验机制，对目标文件实行分级管控：

| 资产类型 | 匹配规则 / 示例路径 | Admin 纳管 | 允许操作 | ES 索引处理 | 安全保护边界与约束 |
|---|---|:---:|---|---|---|
| **活跃日志文件** | `logs/*/*.log` | 是 | 原地截断 `ftruncate(0)` | 记录截断前 offset，异步清理 ES | 必须在注册表白名单；严禁物理 `unlink` |
| **已知轮转日志** | `*.log.1` ~ `*.log.N` | 是 | 原子重命名隔离后 `unlink` | 按 `source_key` 异步清理 ES | 仅允许备份上限（`backup_count`）内文件 |
| **孤儿轮转残留** | `*.log.rotate.*` | 是 | 安全期校验后 `unlink` | 不构造 ES 模糊删除，依赖 ILM | 必须匹配白名单主干；产生时间须超 60 秒安全窗 |
| **清理隔离残留** | `*.cleanup-*` | 是 | 校验未被占用后 `unlink` | 不处理 | 清理中断异常残留；产生超 5 分钟后允许回收 |
| **生产 uWSGI 日志** | `logs/runtime/uwsgi.log` | 是 | 原地截断 `ftruncate(0)` | 视配置异步处理 | v1.1 补录进 `registry.py`，消除生产维护盲区 |
| **进程互斥锁文件** | `logs/**/.__*.lock` | 否 | **绝对保留，禁止触碰** | 不处理 | `ConcurrentRotatingFileHandler` 锁，误删引发死锁 |
| **调度持久化数据库** | `logs/celery/celerybeat-schedule*` | 否 | **受控保护展示，禁止删除** | 不处理 | Celery Beat 调度状态库，Admin 明确标记为非日志资产 |
| **越界/符号链接** | 符号链接、管道、跨根目录 | 否 | **坚决拦截并记录审计** | 不处理 | 严格校验真实物理路径，阻断目录遍历攻击 |

## 3. 核心实现架构与子系统设计

```text
[Wagtail Admin 可观测性中心]
    │
    ├─► [日志概览与文件下钻] ──► registry.py (白名单校验) ──► cleanup.py (ftruncate / orphan unlink)
    │                                                               │
    │                                                               ▼
    │                                                 [MySQL: LogClearAudit 审计台账]
    │                                                               │ (事务强一致)
    │                                                               ▼
    ├─► [生命周期自动归档] ──► Celery Beat (03:30) ──► purge_expired_audits (终态门禁 + 冷备份)
    │                                                               │
    └─► [Outbox 发件箱同步] ──► LogIndexSyncJob ──► Celery Worker ──► [Elasticsearch 日志索引]
```

### 3.1 白名单驱动的日志纳管系统 (`registry.py`)
- 集中注册 `blog`、`base`、`content_ai`、`search`、`observability`、`celery` 及 `runtime/uwsgi.log`。
- 动态扫描白名单主干关联的孤儿文件（`.rotate.<随机串>`），将其归入对应日志源的统计明细中，消除 `du -sh` 与后台统计的不一致。

### 3.2 原地截断与孤儿隔离清理引擎 (`cleanup.py`)
- **活跃日志截断**：通过 `os.open(path, os.O_WRONLY)` 获取文件描述符，调用 `os.ftruncate(fd, 0)` 释放磁盘块并保留 Inode，活跃写入不受任何影响。
- **孤儿文件清理**：针对 `.rotate.*` 文件设立 60 秒安全防抖保护窗；针对 `.cleanup-*` 文件设立 5 分钟安全窗，确认非正在轮转后安全 `os.unlink()`。

### 3.3 审计台账与 180 天生命周期终态归档 (`services.py`, `tasks.py`)
- **终态保护门禁（Terminal State Gatekeeper）**：
  为杜绝因删除审计记录导致级联斩断正在运行或补偿中的 ES 同步任务，清理前必须满足：
  ```python
  Q(created_at__lt=cutoff) &
  Q(state__in=['completed', 'failed']) &
  Q(index_sync_state__in=['completed', 'not_required'])
  ```
  未决状态（`pending`、`running`、`dead_letter`）记录安全豁免，严禁物理删除。
- **冷备份导出机制**：物理删除前，系统自动将超期审计数据导出为压缩 JSON 文件至 `backups/observability/audit_archive_<timestamp>.json.gz`。
- **Celery Beat 定时自动化**：每日凌晨 03:30 自动调用 `cleanup_expired_log_audits`，采用分批删除机制（`batch_size=500`），避免长事务锁表。
- **CLI 管理命令支持**：支持 `python manage.py purge_expired_log_audits [--days 180] [--dry-run]` 便于运维演练与手动治理。

### 3.4 Admin 交互体验升级 (`views.py`, `audits.html`, `log_center.js`)
- **7 列紧凑审计表格**：清晰呈现操作人、日志目标、截断前容量、释放容量、处理成效（醒目高亮失败文件数）、ES 同步状态及时间。
- **原生模态弹窗系统**：重构详情弹窗，采用全局事件委托（`e.target.closest('.js-open-audit-detail')`）、焦点管理（Focus Trap）与 `Esc` 快捷退出，对请求敏感 Token 自动脱敏。
- **快捷时间切片**：提供 `[全部]`、`[今天]`、`[近 7 天]`、`[近 30 天]`、`[近 180 天]` 一键切换。
- **超期主动治理入口**：顶部展示总记录数与超期（>180天）待清理数，提供超管二次确认一键清理。

## 6. 生产运行与运维排障手册

### 6.1 定时任务注册核验
核查 `wagtailblog3/settings/database.py` 中的 Beat 配置：
```python
CELERY_BEAT_SCHEDULE = {
    # 每日凌晨 03:30 自动执行超期审计台账治理
    'cleanup-expired-log-audits': {
        'task': 'observability.tasks.cleanup_expired_log_audits',
        'schedule': crontab(hour=3, minute=30),
        'options': {'queue': 'maintenance'},
    },
}
```

### 6.2 应急运维命令
- **预演超期审计清理（不发生真实删除）**：
  ```bash
  python manage.py purge_expired_log_audits --days 180 --dry-run
  ```
- **手动触发生产超期归档清理**：
  ```bash
  python manage.py purge_expired_log_audits --days 180
  ```
- **冷备份恢复**：
  归档文件默认保存在 `backups/observability/audit_archive_<timestamp>.json.gz`，必要时可通过标准 `gzip -d` 解压恢复审计线索。
