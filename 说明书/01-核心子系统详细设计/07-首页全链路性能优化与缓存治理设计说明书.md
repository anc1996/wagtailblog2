## 1. 现状与性能瓶颈基线

### 1.1 优化前瓶颈实测基线

目标页面：`http://192.168.20.2:6050/zh-hans/`（生产博客首页）。优化前实测基线如下：

| 关键指标 | 优化前基线 | 行业优秀标准 | 根本原因定位 |
|---|---:|---:|---|
| **端到端总时间 (`loadEventEnd`)** | 15.49 秒 | < 1.0 秒 | 境外 Google Fonts 外部阻塞 + 服务端耗时严重叠加 |
| **首字节响应时间 (TTFB)** | 1.65 ~ 2.82 秒 | < 0.2 秒 | 数据库存在大量 N+1 查询，模板片段无缓存 |
| **网络传输体积 (Wire Size)** | 166.5 KB | < 25 KB | 动态 HTML 未开启 Gzip 压缩 |
| **冷链路 SQL 查询次数** | 231 次 | < 15 次 | 热门标签、多级菜单、热门文章均存在循环联表查询 |
| **Google Fonts 单文件耗时** | 约 11.75 秒 | 0 秒 (本地化) | CSS 引入 4 族 42 重外链字体，国内网络跨境高延迟 |

优化前整体瓶颈链路如下：
```text
Google Fonts 境外请求阻塞 (11.75s)
    +
标签/菜单/文章循环触发 N+1 SQL (231次)
    +
动态 HTML 未做模板片段缓存与 Gzip (166.5KB 未压缩)
    =
TTFB 极高、首屏渲染严重阻塞、端到端高达 15.49s
```

## 2. 全链路实现架构（P0 ~ P3 阶段演进）

针对以上四大根因，本工程实施了“前端资源层（P0） $\to$ 数据访问层（P1） $\to$ 应用缓存层（P2） $\to$ 网络传输层（P3）”的四层递进式架构改造。

```text
[浏览器客户端]
    │
    ▼  (P0: 系统字体栈，0 网络阻塞)
[宝塔 6050 Nginx 传输层]
    │  (P3: Gzip on + uWSGI 缓冲区调优，传输体积降至 12.6KB)
    ▼  (unix socket)
[uWSGI / Django 应用层]
    │
    ├─► [Redis 缓存层] (P2: 模板片段缓存 300~600s，热缓存 SQL 降至 6 次)
    │        ▲
    │        └─ (P2: Wagtail hooks 生命周期精准失效，严禁 cache.clear)
    │
    └─► [MySQL 数据层] (P1: ORM 反向单条聚合 + Treebeard 内存级菜单 + 预取优化)
```

### P0：前端资源层 —— 剥离 Google Fonts 与系统字体栈演进

- **改造文件**：`wagtailblog3/static/gretzia/css/style.css`
- **实现方案**：彻底移除顶部 `@import url("https://fonts.googleapis.com/...");` 引入的 4 族 42 重境外外链。
- **字体栈契约**：采用跨端高 DPI 现代系统字体栈：
  ```css
  font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue", Arial, "Noto Sans", sans-serif, "Apple Color Emoji", "Segoe UI Emoji", "Segoe UI Symbol";
  ```
- **落地效果**：消除了原本长达 11.75 秒的跨国字体握手阻塞，实现零网络依赖极速排版。

### P1：数据访问层 —— 数据库 N+1 治理与预取架构重构

#### 1. 热门标签反向聚合统计
- **改造文件**：`wagtailblog3/apps/blog/templatetags/blog_tags.py`
- **核心实现**：将原本逐个文章遍历 `page.tags.all()` 的 Python 循环改为单条 ORM 反向聚合统计，仅统计已发布（`live=True`）的页面：
  ```python
  @register.inclusion_tag('blog/components/top_tags.html', takes_context=True)
  def top_tags_sidebar(context, limit=6):
      """通过数据库级单条聚合统计已发布文章的热门标签，消除 N+1 循环查询"""
      top_tags = (
          Tag.objects
          .filter(blog_blogpagetag_items__content_object__live=True)
          .annotate(num_times=Count('blog_blogpagetag_items'))
          .order_by('-num_times', 'name')[:limit]
      )
      return {'tags': top_tags, 'request': context.get('request')}
  ```
- **落地效果**：标签模块 SQL 次数从原本的 **160 次骤降至 1 次**。

#### 2. 多级递归导航菜单内存级优化
- **改造文件**：`wagtailblog3/apps/blog/templatetags/blog_tags.py`
- **核心实现**：利用 Wagtail 底层 Treebeard 的 `numchild` 属性预先拦截无子节点的页面，剔除昂贵的级联多表联查 `specific()`，使用内存级 `is_descendant_of` 判定活动菜单高亮。
- **落地效果**：彻底消除菜单渲染阶段的级联递归数据库回源。

#### 3. 热门文章与博客索引预取优化
- **改造文件**：`wagtailblog3/apps/home/models.py`
- **核心实现**：在 `popular_posts` 与 `blog_indexs` 的上下文查询中接入预加载，并保持 Lazy QuerySet，避免过早求值：
  ```python
  def popular_posts(self):
      """预取特色图与关联分类，避免模板渲染触发级联查询"""
      return (
          BlogPage.objects.live()
          .public()
          .select_related('featured_image')
          .prefetch_related('categories')
          .order_by('-first_published_at')[:4]
      )
  ```
- **落地效果**：消除分类标签与横幅图片的隐式额外 SQL。

### P2：应用缓存层 —— Redis 模板片段缓存与精准淘汰机制

#### 1. 模板片段粒度缓存设计
- **改造文件**：
  - `wagtailblog3/templates/home/home_page.html`
  - `wagtailblog3/templates/includes/header.html`
- **缓存策略矩阵**：

| 缓存片段 | 缓存 Key 维度 | TTL | 隔离维度 |
|---|---|---:|---|
| **主导航菜单** | `header_nav_menu` | 600 秒 | 语言代码 (`request.LANGUAGE_CODE`)、当前页面 ID (`page.id`) |
| **首页轮播图** | `home_banner_carousel` | 600 秒 | 语言代码、页面 ID |
| **热门文章模块** | `home_popular_posts` | 300 秒 | 语言代码、页面 ID |
| **文章归档列表** | `home_archive_list` | 600 秒 | 语言代码、页面 ID |
| **热门标签排行** | `home_popular_tags` | 600 秒 | 语言代码、页面 ID |

#### 2. 生命周期驱动的精准缓存失效引擎
- **改造文件**：`wagtailblog3/apps/blog/wagtail_hooks.py`
- **核心实现**：注册 Wagtail 页面生命周期钩子（发布 `after_publish_page`、修改 `after_edit_page`、删除 `after_delete_page`）。仅定向淘汰首页片段缓存键，**严禁使用全局 `cache.clear()`**，避免击穿全站其他业务缓存：
  ```python
  def _invalidate_home_fragments():
      """定向淘汰首页片段缓存，安全支持多语言前缀"""
      languages = [code for code, _ in getattr(settings, 'LANGUAGES', [('zh-hans', '中文')])]
      keys_to_delete = []
      for lang in languages:
          keys_to_delete.extend([
              f"template.cache.home_popular_posts.{lang}",
              f"template.cache.home_popular_tags.{lang}",
              f"template.cache.home_archive_list.{lang}",
              f"template.cache.home_banner_carousel.{lang}",
              f"template.cache.header_nav_menu.{lang}",
          ])
      cache.delete_many(keys_to_delete)
  ```

### P3：传输层 —— 宝塔 6050 端口 Nginx 调优与 uWSGI 缓冲

- **配置文件**：`/www/server/panel/vhost/nginx/html_wagtailblog.docs.conf`
- **关键调优项**：
  1. **开启全量动态 Gzip 压缩**：核心设置 `gzip_proxied any;`（解决 uWSGI 反向代理响应未被 Nginx 压缩的关键根因），设置压缩级别 `gzip_comp_level 6;`；
  2. **uWSGI 性能缓冲**：配置 `uwsgi_buffering on;`、`uwsgi_buffer_size 32k;`、`uwsgi_buffers 8 32k;`，防止大响应阻塞 uWSGI 进程。

## 6. 架构师裁定闭环与后续运维建议

### 6.1 架构师前序疑问之落地决议（已结案）
1. **字体授权策略**：放弃引入任何需外部网络下载的第三方字体，确立跨端高 DPI 系统字体栈为全站长期标准。
2. **标签统计语义**：确立以 `content_object__live=True` 为唯一准则，通过 ORM 关系表聚合，严禁在 Python 内存中对全量文章循环统计。
3. **菜单与组件缓存**：确立以语言代码（`LANGUAGE_CODE`）和当前页面 ID 为天然隔离键，防止多语言串标。
4. **失效策略**：全面确立“Wagtail Hook 生命周期事件精准淘汰特定 Key”，永久禁止在业务事件中触发全局 `cache.clear()`。

### 6.2 中长期运维监控建议
1. **Redis 命中率观测**：建议在中长期运维中，针对 Redis 的 `info stats`（`keyspace_hits` / `keyspace_misses`）增加周期性巡检脚本或集成 Prometheus 仪表盘。
2. **宝塔 Nginx 重复警告清理**：宝塔生成的 `location /static/` 中包含的 `types { application/javascript js mjs; }` 与内置 `mime.types` 重复声明了 `js`，虽然不影响服务，后续可在宝塔界面微调消除该语法告警。
