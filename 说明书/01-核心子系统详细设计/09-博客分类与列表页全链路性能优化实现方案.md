# 博客分类与列表页全链路性能优化实现方案

## 1. 方案背景与性能成果对比

### 1.1 优化前主要痛点与瓶颈
1. **N+1 与正文冗余拉取**：列表页查询逐篇加载完整 Page 实例及 StreamField，拉取未展示的 MongoDB 正文，默认 20 篇列表触发 182 次 SQL；
2. **侧边栏性能黑洞**：每次请求对全站文章执行 `TruncYear` / `TruncMonth` 聚合，且作者推荐使用 `Author.objects.order_by('?')` 触发 MySQL 磁盘全表随机排序；侧栏 HTML 体积高达 91.2 KB；
3. **前端人为强制白屏**：`base.html` 注入全屏 `.preloader` 遮罩与 1500ms 强制 `setTimeout` 延迟，首屏感知极慢；
4. **失效粗暴**：发布文章时容易滥用全局 `cache.clear()` 导致全站缓存雪崩。

### 1.2 生产上线实测前后指标对比

| 核心指标 | 优化前基线 | 优化后实测数据 (生产机 192.168.20.2) | 优化倍数 / 收益 |
| :--- | :--- | :--- | :--- |
| **分类慢页面首屏 (122 篇)** | > 10,000 ms (10s+) | **冷启动 205 ms / 热缓存 70.41 ~ 79.30 ms** | **提速超 100 倍** |
| **AJAX 分页接口 (Page 2)** | ~ 1,200 ms | **冷启动 44 ms / 热响应 39.35 ~ 47.17 ms** | **提速超 25 倍** |
| **业务 SQL 次数 (每页 20 篇)** | 182 次 | **冷缓存 8 次 / 热缓存 0 次** | **SQL 压降 95.6% ~ 100%** |
| **StreamField 正文加载** | 每篇完整反序列化 | **`.defer('body')` 零加载正文** | **BSON 解析消耗归零** |
| **侧边栏 HTML 体积** | 91.2 KB | **12.9 KB** (更早年份优雅收拢) | **体积精简 85.8%** |
| **作者随机推荐** | `ORDER BY RAND()` 慢查询 | **小时桶确定性哈希，0 慢查询** | **彻底消除全表扫描** |
| **首屏加载白屏时间** | 强制等待 1,500 ms | **0 ms 纯服务端渐进渲染 (Preloader 移除)** | **消除首屏人为卡顿** |

## 2. 核心架构与 DTO 装配引擎

### 2.1 批量装配与延迟加载（`wagtailblog3/apps/blog/services/listing.py`）
- **ListingCard DTO**：定义轻量强类型数据类，仅封装列表卡片渲染所需的字段（标题、URL、发布日期、封面图、分类、作者、摘要），严禁将 MongoDB 正文载荷带入列表缓存；
- **`.defer('body')` 零正文读取**：QuerySet 查询强制切断 `body` 字段加载，消除对 MongoDB 的反序列化开销；
- **批量预取关系对象**：一次性使用 `select_related('owner')`、`prefetch_related('tagged_items__tag', 'categories')` 完成外键装配，消除模板渲染期的 N+1 访问；
- **Single-Flight 防击穿**：使用 Redis 分布式互斥锁，保障同参数并发冷请求仅由单一线程执行底层装配，其余线程等待复用，杜绝缓存击穿。

## 3. 侧边栏归档与作者推荐重构

### 3.1 归档聚合树轻量缓存（`wagtailblog3/apps/blog/services/sidebar_cache.py`）
- **站点/语言/公开严格隔离**：按 `(site_id, locale_id)` 分组生成聚合树，缓存 TTL 为 24 小时；
- **结构优化与交互修复**：仅对**最近 3 年**（如 2026、2025、2024）渲染 `+` 号展开交互；更早年份归档标记为 `archive-year-older` 默认收拢，彻底消除历史年份无文章月份的虚假展开；
- **侧边栏 DOM 压降**：体积从 91.2 KB 骤降至 12.9 KB，降低移动端解析与渲染开销。

### 3.2 作者推荐算法优化（`sidebar_cache.py`）
- **消除 `ORDER BY RAND()`**：改为一次拉取有效作者候选池（带 30 分钟缓存），基于 `(site_id, locale_id, hour_bucket)` 进行确定性哈希轮换；
- 每小时平滑轮播推荐作者，SQL 消耗降为 0，彻底解除了 MySQL 内存临时表与文件排序压力。

## 4. 生命周期精准失效契约

### 4.1 代次原子推进（`wagtailblog3/apps/blog/services/listing_invalidation.py`）
- **代次版本键（Generation Key）**：各分类和列表维护独立的整数代次版本号；
- **事务提交后推进**：在 Wagtail 页面发布、取消发布或删除钩子中，注册 `transaction.on_commit`，在数据库持久化成功后原子自增代次计数器：
  - `wagtail_hooks.py` 挂载 `after_publish_page`、`after_unpublish_page`、`after_delete_page`；
  - 仅推进受影响的站点与分类代次，旧缓存自然失效过期；
- **严禁全局清空**：全局杜绝 `cache.clear()` 与 `FLUSHDB`，保障全站热点数据与其他业务模块零抖动。

## 5. 前端视觉自愈与渐进增强

### 5.1 消除 Preloader 白屏遮罩
- 从 `templates/base.html` 移除全屏 `.preloader` 元素，删除 `static/gretzia/js/script.js` 中的 1500ms 延迟器，使页面达到浏览器即开始流式渐进渲染；
- 脚本增加 `defer` 属性，样式通过 CSS 变量系统统一收拢。

### 5.2 首页“热门阅读”卡片自愈
- **封面回退机制**：文章无主图时自动加载默认封面兜底，杜绝布局塌陷；
- **Isotope/Masonry 图片就绪重排**：监听 `imagesLoaded` 事件，在封面图片渲染完成后触发布局重排，根除高度坍塌与横向原生滚动条。
