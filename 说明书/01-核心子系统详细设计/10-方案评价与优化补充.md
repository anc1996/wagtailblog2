# Wagtail Page 正文外置通用协议：方案评价与优化补充

> 评审状态：研发方案待评审；本文件不是实现证明。三份相关文档都属于方案阶段。当前工作区没有通用外置正文实现，也未执行测试库或生产库变更。
>
> 评审基线：仓库 `AGENTS.md`、`.codex/`、现有 Django/Wagtail 源码、搜索模板与服务，以及正文外置详细设计和分步计划草案。生产搜索页仅做匿名只读 GET；没有连接生产数据库。

## 结论

“由新 Page 子类显式继承 mixin 并选择字段启用通用 Mongo 正文存储；未继承的普通 Page 保留原有行为”是可行方向。既有 BlogPage 继续使用自己的 Mongo 专用链路。它不是单一模型抽象，而是正文存储、Wagtail Revision/发布生命周期、搜索注册与索引、跨来源分页、分析统计、备份恢复共同组成的改造。

推荐按三个独立契约实现：

1. `ExternalContentPageMixin` + 模型级 `content_storage` 是字段外置 opt-in；通用 coordinator 处理 Revision 字段集合与 Mongo 不可变版本，注册表按真实 Field 类型匹配 codec。其他 Page 不进入这条链路。
2. Search Type Registry 独立登记是否可检索、稳定类型键、投影适配器、日期语义和公开范围；正文外置本身不能隐式公开页面。
3. 类型化搜索分析单独记录用户选择范围、返回结果类型和可选点击事件；不得把 Wagtail `QueryDailyHits` 的无类型聚合伪装成新维度。

后续实现可分阶段推进。用户已确定首期试点为全新、无历史数据的 `guides.GuidePage`，独立 `guides` 应用中的 `GuideIndexPage` 作为原生 MySQL 父页；业务 Page 只外置 `body: StreamField`。专用测试 Page 以两个 StreamField 外置字段加一个原生字段证明内核可复用。现有 HomePage、PortfolioPage 不加 mixin、不迁移、不改动正文归属。试点验收后依次开放 RichTextField、TextField codec，内容型 JSONField 待实际业务 schema 确定；首期不做全 Page 强制外置或既有 BlogPage 历史正文搬迁。多字段 StreamField 内核及首个业务试点暂按 9–11 个工作周估算，RichText/Text codec 扩展初估另需 2–3 个工作周，实际范围和资源门禁见分步计划；这不是生产发布时间承诺。

## 架构选择与取舍

| 选项 | 优点 | 主要代价 | 判断 |
|---|---|---|---|
| 所有 Page 自动 Mongo 化 | 无需开发者选择。 | 破坏 Wagtail 默认存储语义，短字段/特殊表单都卷入 Mongo，兼容面和恢复风险最大。 | 不采用。 |
| 新 Page 继承 BlogPage 或复制 BlogPage 实现 | 早期可复用现有 Blog 代码。 | 带入作者、标签、评论、Feed、缓存和 Blog 专属 Mongo/搜索/删除规则，通用页面持续被 Blog 模型绑架。 | 不采用。 |
| Page 子类显式继承薄 Mixin，按 `content_storage` 选择字段；codec 自动匹配，搜索另外登记 | 未继承者无 Mongo 副作用，Page 业务模型继续拥有字段定义；新增字段复用同一生命周期 coordinator。 | 需正确接入 Wagtail Revision 与原生发布各入口，并扩展搜索来源、analytics 和补偿服务。 | 推荐。 |

### 稳定的数据边界

- MySQL/Wagtail 继续是 Page 树、model identity、权限、locale、工作流、短字段、Revision 元数据和正式指针的权威来源。MongoDB 是已登记字段不可变版本的 payload 来源；Elasticsearch 是可重建搜索投影。
- 首期新增集合 `external_content_versions`；旧 BlogPage 集合/格式不迁移不重命名，由 adapter 双读/兼容现有写链路。集合具体 BSON 字段与唯一索引须以详细设计定稿并经测试验证。
- MySQL Page 表和 Revision.content 保留稳定字段/key；只有显式外置字段写中性占位值及 `_external_content_manifest`，未列字段保留原生值。外置 payload 不经意写回关系库；普通 ORM 字段直读只得到占位值。
- Mixin 与 search type registry 分离：Page 即使正文在 Mongo，未注册公开 search adapter 仍不进入搜索，包括默认普通 Page 来源；普通 MySQL Page 也可注册独立搜索类别。
- 搜索 all 的范围是 Blog、明确注册的 专题指南 类型、剩余普通 Page 的互斥并集；普通来源排除所有未注册外置 Page。以全局 Wagtail `Page.pk` 去重，同时保存类型元信息供筛选、结果卡片和统计使用。
- 搜索统计分别记录用户请求的 scope 与结果/点击的 type。单次 all 请求只计一次；已有历史 QueryDailyHits 只能继续作为总量。

### 字段外置边界

Page 模型以 `content_storage = {"body": "mongo"}` 显式选择字段；框架只对这些字段按真实 Field 类型解析 codec，不按类型、字段名或长度自动外置。未知、歧义或禁入字段启动检查失败；Manifest 记录 `content_storage_schema` 和每字段选定的 codec/schema/version/hash。适合候选的是由单个 Page 修订拥有、通常整体读取、不参与 MySQL 筛选/排序/权限决策的长正文：StreamField、长篇 RichTextField、原始 Markdown/转录稿等 TextField；内容型 JSONField 需先确定 schema 和实际用途。标题、slug、日期、Locale、权限、作者、分类、标签、短摘要、关系及工作流/Outbox/统计状态仍留 MySQL，文件和图片继续使用现有媒体存储。RichText/StreamField 内嵌 Page 或图片引用仍须维护引用与删除保护。

首个业务试点只声明 body，注册表匹配 `streamfield.v1`；首期内核已经需要对字段集合统一编排，并用专用测试 Page 验证双外置字段。后续 `richtext.v1` 保存 Wagtail 原始富文本字符串，`text.v1` 保存原始文本/Markdown；codec 只负责无损转换、空值、规范化和必要的投影提取，Revision、发布、Copy/Alias、清理由同一 coordinator 处理。Mongo 各字段版本全部成功后才能在一个 MySQL Revision Manifest 中引用整组字段；任何字段失败都不能留下可用的部分修订，未引用版本按安全期和全引用复核进入孤儿治理。已有字段改存储位置必须另做版本化迁移、历史读取和回退，不得只改配置。

## 主要风险及控制

| 风险 | 控制和放行证据 |
|---|---|
| 发布版本和 Mongo 正文错配 | Manifest 全身份检查；目标 Revision 锁定；fault injection 证明 Mongo 失败不推进 Page live、正式指针和搜索代次。 |
| Wagtail 原生入口覆盖不全 | 阶段 0 核对源码；每个后台按钮/Workflow/定时路径有集成测试；不靠 `BlogPage.publish()` 单一方法。 |
| 搜索开关关闭使正文发布状态缺失 | 发布状态是内容正确性，不得受 Search producer feature flag 控制；搜索事件可禁用时，正式指针仍正确提交。 |
| 老事件重放复活下架内容 | MySQL State/outbox 代次单调；ES tombstone 保留代次；旧 UPSERT 被 superseded；重放测试验证。 |
| Page 权限或 locale 越界 | 每个结果来源统一 Wagtail `.live().public()`、父级限制/locale 检查；ES 结果回到 MySQL 按 Page ID/类型复核；限制变化重算 scope。 |
| 跨来源游标漏项、重复项 | cursor 绑定 query/type/date/order/locale 与 registry version；保留来源未消费候选，消费真实数量推进；覆盖三路 rank/date ties 和重复 ID。 |
| 统计隐私及口径漂移 | query normalization、有限保留和最小字段；HTML/API/AJAX/缓存/重试/分页使用统一计数点；不保存正文、身份凭证。 |
| 备份跨库不一致或不可恢复 | 写入暂停/恢复点记录；MySQL+Mongo 隔离 restore 和引用/hash 对账；记录 RPO/RTO、摘要及 Checker 签认。 |
| 任意历史迁移风险 | 首期不改存量 Revision，不做批量 BlogPage 数据搬迁；Schema 和 pointer 迁移独立评审；需要迁移时另立任务、另授权、可小批对账。 |
| 草稿 Revision ID 复用 | 阶段 0 验证 Wagtail 8.0 overwrite 语义；已批准、发布、排期或被 Workflow 引用的 Revision 禁止覆盖；若不能安全识别引用，外置 Page 一律新建 Revision ID。历史读取按 Manifest，不用 ID 推断正文版本。 |
| 跨库发布半成功 | Mongo 全字段不可变版本先确认写入，MySQL 中 Page/Revision/正式 Manifest/Outbox 同事务提交；MySQL 失败产生不可见孤儿供延迟治理，ES 失败由 Outbox 重试；不宣称存在跨 MySQL、Mongo、ES 的单一事务。 |
| MySQL 恢复比 ES 旧 | 冻结投递、隔离旧 Worker/租约，从恢复后的正式 Manifest 在新物理索引及版本域重建，核对后切换 alias；验证旧 Worker 迟到事件不会覆盖新结果。 |
| 字段存储策略变更 | `content_storage_schema` 固定 Revision 当时策略；旧 Revision 继续按旧策略读取。已有字段改变存储位置必须另立迁移、对账及回退计划，不能只改 `content_storage`。 |
| 旧结构解码丢失 | 保留历史字段名映射和 StreamField 块解码器；无 Manifest 仅按已识别的旧 Blog/原生 MySQL 读取，新协议 Page 缺 Manifest 即失败。 |
| 搜索旧命中泄漏 | 返回前同时复核当前权限、正式 Manifest 摘要和公开代次；不符时丢弃旧摘要/缓存并重新投影。未注册外置 Page 排除默认普通来源。 |
| Alias 指针跨页 | Alias 目标按自己的 page_id 派生全部字段的不可变版本；来源关系只用于同步和审计，不直接复用源身份指针。 |

## 上线及恢复建议

上线前备份是未来生产变更的必需门禁，本轮没有执行：源码和配置基线、MySQL Page/Revision/状态/Outbox、Mongo 相关旧集合与新版本集合、ES alias/mapping/serving 索引均纳入恢复计划。跨 MySQL 与 Mongo 不具备分布式原子快照时，应在获批窗口暂停正文写入并记录统一高水位；否则须保留跨库对账和向前补齐方案，不能声称备份点天然强一致。

正式启用前必须把备份恢复到隔离环境，证明 Revision Manifest 中全部字段对应 Mongo payload 的模型/页面/字段/哈希一致；确认 ES 可按已发布版本在新版本域重建或 alias 可回退。写入新协议之后，回滚应先停新写入、保留新旧双读和 Mongo 不可变版本；不得简单移除 mixin、清空 Mongo 或从旧备份覆盖新写入。

生产逐步发布由 Sol/Maker-Checker 清单、用户单独授权和维护窗口约束；需要实际访问生产数据库的只读盘点/备份同样受数据访问和运维授权约束。没有部署证据前，不得把拟定工期、备份动作或生产验证写成已完成。

## 尚待产品/实施阶段确认

1. 业务名和搜索类型已确定：`guides.GuidePage`、`guides.GuideIndexPage`、显示名“专题指南”、稳定搜索键 `guides`。页面 URL 由实际 Wagtail 页面树及 Site/Locale 决定；首期预计索引页 slug 为 `guides`，创建时核对冲突。
2. 业务试点已固定仅有一个外置 `body: StreamField`；专用测试 Page 须验证双外置字段加一个原生字段。指南的摘要、主题、难度、最后核查日期、封面、关联阅读及公开范围见《11-专题指南页面需求与详细设计说明书》；RichText/Text codec 作为试点后扩展，JSONField 需先有明确的内容结构。
