# 专题指南页面需求与详细设计说明书

> 状态：已确认业务方向，待研发实现。本文是 `GuidePage` 的业务契约；通用正文协议以同目录《10-Wagtail Page正文外置通用协议详细设计说明书》为准。本文所列新应用、模型、索引及页面均尚未落地。

## 1. 目标与现状

专题指南为用户提供有顺序、可核查的操作路径。前台需要独立导航、专题列表和指南详情；全站搜索增加“专题指南”类别。指南与博客是不同内容类型，不继承 `BlogPage`，不带入博客作者、评论、Feed 或专用 Mongo 指针。

当前仓库应用位于 `wagtailblog3/apps/`，`settings/base.py` 尚未登记 `external_content`、`guides`；`templates/search/search.html` 和搜索服务只识别 `all/blog/pages`。`templates/includes/header.html` 通过站点根页第一层子页面生成主菜单。`BlogPage` 已有自己的 Mongo 兼容链路，`HomePage.body`、`PortfolioPage.body` 仍归 MySQL。本需求不迁移任何历史页面或正文。

## 2. 页面与信息架构

| 模型 | 身份及页面树 | 数据归属 | 前台行为 |
|---|---|---|---|
| `GuideIndexPage` | `guides` 应用原生 Wagtail `Page`；一个站点/Locale 下作为指南入口，优先挂在该站点根页下一层；只允许 `GuidePage` 为子页 | 自身标题、简介、SEO、导航属性等原生 MySQL Page/Revision；不继承外置 mixin | `/guides/` 为拟定站点路径，实际 URL 由 Wagtail 页面树和 slug 决定；列表展示公开子页、摘要、主题、难度、最后核查日期、封面，分页及筛选采用稳定排序 |
| `GuidePage` | 仅允许建在 `GuideIndexPage` 下；`guides.GuidePage` 为稳定模型身份 | 显式继承 `ExternalContentPageMixin`，仅 `content_storage = {"body": "mongo"}`；其余字段及 Wagtail 状态归 MySQL | 详情显示导读、步骤、代码、提示、FAQ、参考资料、相关文章和最后核查日期；SEO 摘要来自 MySQL，不在公开缺失正文时拿草稿兜底 |

编辑者先创建并发布索引页，再创建指南。索引页是否进入主导航，取决于现有 `generate_menu_items` 的公开性与菜单规则；实现阶段需验证缓存失效和移动、下架、Locale 行为，必要时只在现有导航规则中加明确类型处理，避免写死 URL。多个 Site 或 Locale 使用各自页面树，不用全局第一条索引页决定链接。

### 2.1 GuidePage 字段

| 字段 | 设计 | 权威存储与用途 |
|---|---|---|
| `title`、`slug`、`search_description` | Wagtail Page 原生字段 | MySQL；路由、SEO、搜索标题 |
| `summary` | 简短纯文本，设长度上限；编辑界面提示填写 | MySQL；列表卡片、搜索摘要、分享描述；不从 Mongo 正文动态截取 |
| `topic` | 指向 `guides.GuideTopic` 的外键；`GuideTopic` 为 MySQL/Wagtail Snippet，具有唯一稳定 slug 和显示名；被引用时限制删除 | MySQL；列表筛选、搜索过滤；展示名可改，slug 变更须评估旧链接与筛选缓存 |
| `difficulty` | 固定枚举：入门、进阶、深入；数据库值使用稳定英文键 | MySQL；展示、筛选；更名须保留旧值兼容 |
| `last_reviewed_at` | 可为空的核查日期，区别于 `first_published_at` 和修订时间；不得由普通保存自动更新 | MySQL；读者可信度提示、按核查日期排序；编辑者确认内容后手动填写 |
| `cover_image` | 可为空，关联当前 `WAGTAILIMAGES_IMAGE_MODEL = 'blog.BlogImage'`；采用现有图片存储及 rendition | MySQL 外键；列表、详情和分享图；删除图片后可降级 |
| `related_pages` | 有顺序且有数量上限的 Wagtail Page 关联，仅选可访问页面；建议 `ParentalKey` + `Orderable` + Page chooser | MySQL 关系；详情只输出当前公开、同站点/Locale 且可访问的目标；循环引用不递归渲染 |
| `body` | `StreamField(use_json_field=True)`；唯一外置字段 | Mongo `external_content_versions` 不可变 payload；MySQL 行与 Revision 只保存安全空哨兵及 `_external_content_manifest` |

`GuideTopic` 的初始词表由编辑者在后台维护；空主题可保存草稿，公开发布时要求选择有效主题。`related_pages` 若指向其他指南或博客，公开渲染必须重新核验目标可见性，不能只信创建时 chooser 的合法性。封面和相关文章不是 Mongo 正文的一部分。

### 2.2 正文块与编辑体验

`body` 首期限定七种有顺序的顶层块，均走同一个 `streamfield.v1` codec 与 Manifest：`lead`（导读）、`step`（步骤，包含标题、说明及可选图片）、`code`（语言和原始代码）、`tip`（提示/警告及正文）、`faq`（问题与回答）、`reference`（标题、URL、可选来源说明）、`markdown_block`（原始 Markdown 长段落）。步骤和 FAQ 保持块 ID 及嵌套顺序；外链按站点现有安全规则渲染，不接受任意 HTML。导读可选；至少一个步骤才允许公开发布，草稿允许未完成结构。块名称和 schema 一旦产生 Revision 不随意改名；后续修改须有旧块解码与迁移策略。

`markdown_block` 持久化值保持原始 Markdown 字符串，key 固定为 `markdown_block`；HTML 只在模板渲染阶段生成。首版块可使用 Wagtail 原生文本/富文本与现有安全渲染组件，代码原文不可在入库时转义或转换为 HTML。选择图片、文档或内部页面的块需在复制、翻译、删除及公开渲染时保护引用。

编辑面板按“指南信息 / 正文 / 关联阅读”分组，字段帮助文案解释核查日期和难度；列表卡片与详情页采用共享的封面、难度、主题视觉语言。响应式断点、键盘导航、图片 alt、标题层级、代码横向滚动、FAQ 展开状态和空态需在前端验收。

## 3. 外置正文和 Wagtail 生命周期

`external_content` 应用拥有 mixin、字段策略检查、codec、Mongo repository、Revision coordinator、发布状态、复制/别名/翻译与删除补偿；`guides` 只拥有模型、块、编辑面板、视图上下文和模板，不复制 Blog 专属发布逻辑。模型必须显式 opt-in；启动检查确认 `body` 是已注册 StreamField，`summary/topic/difficulty/last_reviewed_at/cover_image/related_pages` 不可被外置。通用内核仍需由专用测试 Page 验证“两外置 StreamField + 一原生字段”，GuidePage 只有一个外置字段。

Revision 的 `_external_content_manifest` 记录策略版本、`guides.guidepage`、Page ID 及 `fields.body` 的 codec、schema、version ID、SHA-256。每次保存草稿先写不可变 Mongo payload，再在 MySQL 事务内保存 Page/Revision/草稿指针；失败的 Mongo 文档保持不可见，延迟按引用复核回收。读草稿、未保存预览、历史恢复、比较、发布与前台都须精确读取对应 Revision 或正式 Manifest，校验模型、页、字段、版本及哈希；异常不回落到其他修订或 Blog 正文。普通序列化不得触发 Mongo 写入。

发布由通用服务协调 Wagtail 原生 Action，正式指针与 `live`/已发布 Revision 在同一 MySQL 事务推进；`CONTENT_SEARCH_PRODUCER_ENABLED` 只控制可选搜索生产，不控制正文发布。Workflow 批准、定时发布、取消、重复回调和并发编辑必须锁定相应 Page/Revision；已获批准或已发布 Revision 不得被草稿覆盖。未来定时任务仅在实际生效时切换正式正文。复制与翻译派生目标 Page 独立 Mongo 版本；Alias 不能共享源页绑定的可变指针。对 Wagtail 8.0 尚未证明安全的入口显式阻断并给出后台错误，待门禁通过再开放。

删除包括父页级联和批量入口：先持久化删除意图、精确版本引用清单及搜索 tombstone，再阻断新引用；只有复核所有 Page/Revision/Workflow/Alias/Outbox 引用后才可延迟回收 Mongo 版本。任何正文损坏或 Mongo 故障下，公开详情应失败关闭并记录告警，不展示不匹配或草稿内容。业务模板不自行读取 Mongo，统一通过受控 published reader。

## 4. 搜索、导航与前台契约

搜索稳定类型键为 `guides`，显示名“专题指南”。`blog` 仅 BlogPage，`guides` 仅 GuidePage，`pages` 为余下已登记公开 Page 且排除所有未注册的外置页面；`all = blog ∪ guides ∪ pages`，按 Wagtail Page ID 去重。GuideIndexPage 作为原生入口页归 `pages`；其正文不进 Mongo。`type=guides` 复用统一搜索入口，指南导航可链接到索引页及预置筛选的全站搜索，不能建立另一套查询规则。

搜索索引只投影当前正式 Manifest 所指正文的安全纯文本，并组合 MySQL 的标题、摘要、主题、难度、核查日期及公开时间。`last_reviewed_at` 是展示与业务筛选字段，现有全站“发布时间”仍以 Wagtail `first_published_at` 为统一排序/日期过滤语义，不混用。索引文档、Outbox 与命中复核携带 model label、search type、Page ID、正式 Manifest 摘要与公开代次；ES 命中返回前重查当前 live/public、祖先访问限制、Site/Locale 和正式版本。旧 Blog 索引别名保持兼容，新来源的物理索引及别名经实施阶段实测确认，不能先假定已存在。

同步修改搜索 HTML、AJAX 片段、REST API、前端 JS、缓存 namespace、cursor 签名、结果卡片与分页。缺源、超时和索引滞后需要明确失败/降级规则，不能把搜索故障记为零结果。统计 `search_scope` 取 `all/blog/guides/pages`，`result_type` 标记实际曝光或点击类型；一次 `all` 请求只记一次查询，历史无类型统计不回填猜测。

专题列表仅查询当前索引页的已发布公开 GuidePage 子页，默认让有核查日期的指南优先，再按核查日期倒序、首次发布时间倒序、Page ID 倒序稳定分页；主题、难度筛选参数须白名单验证，空列表有可理解的提示。详情页展示同站点/Locale 的面包屑、更新时间语义、TOC/步骤定位、相关文章和参考资料。导航缓存需在索引页创建、发布、移动、下架及权限变更后可收敛，并验证桌面与移动菜单入口。

## 5. 备份、恢复与回滚

新指南无历史迁移，但首次启用仍需对 MySQL Page/Revision/外置状态、Mongo `external_content_versions` 与 ES 索引取同一可解释的恢复点。恢复演练在隔离环境完成：逐 Revision 校验 Manifest 与 payload 身份/哈希，重建正式搜索投影并检查导航与权限。若 MySQL 恢复点早于 ES，冻结投递并以新 `recovery_epoch` 和新物理索引重建、核对后切换 read alias；旧 Worker 被围栏阻止写入新索引。回滚时先停新格式写入，保留已写 Mongo 版本、旧解码器和 Manifest 读路径；不得移除 mixin 后继续服务已外置页面，更不得清空集合。

## 6. 验收门禁

1. 后台可创建、编辑、预览、发布索引与指南；GuideIndexPage 原生 MySQL，GuidePage 仅 `body` 外置，摘要和所有分类/关系字段在 MySQL 且 Revision 可追溯。
2. 七类块往返、块 ID/顺序、原始 Markdown、代码、图片/链接引用正确；草稿、历史、Workflow、定时、复制、别名、翻译、取消及删除逐入口受控。
3. 故障与竞态注入证明 Mongo 失败不推进 live/指针，旧回调不覆盖新发布，索引迟到事件不复活已下架指南，跨页/哈希错误绝不读出正文。
4. 导航、列表、详情、搜索四类范围、搜索 API/缓存/cursor、权限、Locale、移动端和无障碍检查通过；`all` 无重复、漏项和私有结果。
5. 隔离恢复演练能重建正文与搜索；BlogPage、HomePage、PortfolioPage 无回归。实施与验证步骤见《11-专题指南与正文外置分步实施计划》。

此文档是研发设计，不代表已完成测试或部署。生产验证完成后按仓库规范与实施计划合并成精简《实现方案》。
