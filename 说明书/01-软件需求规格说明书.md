# WagtailBlog3 软件需求规格说明书

**文档用途**：产品、开发、测试、运维共同使用的现行需求基线。**代码基线**：仓库 `main`，Django 5.2.8，Wagtail 7.4.2。

## 1. 系统边界

项目根包为 `wagtailblog3`，业务代码位于 `wagtailblog3/apps/`。站点由 Wagtail 页面树驱动，Django URL 在 `wagtailblog3/urls.py` 注册后台、博客、归档、评论、搜索和页面兜底路由。生产入口只能由 Nginx/uWSGI/systemd 提供；开发入口为 Django `runserver`。

## 2. 业务功能

| 领域 | 代码位置 | 维护入口 |
|---|---|---|
| 首页 | `apps/home/models.py` | `HomePage.get_context()`、`templates/home/` |
| 博客 | `apps/blog/models.py` | `BlogIndexPage`、`BlogPage`、`BlogPageForm` |
| 标签/分类/作者 | `apps/blog/models.py`、`services/tag_listing.py` | 页面 context 和 `blog/urls.py` |
| 图片/文档/媒体 | `apps/blog/blocks.py`、`admin_image_upload.py` | Wagtail chooser、MinIO storage |
| 评论/回复/表情 | `apps/comments/` | `comments/urls.py`、session/CSRF |
| 归档 | `apps/archive/` | `services/listing.py`、year/month views |
| 作品集 | `apps/portfolio/` | `PortfolioPage` |
| 搜索 | `apps/search/` | SSR、JSON API、建议、后台分析 |
| 观测 | `apps/observability/` | 日志解析、审计、ES 日志索引 |

## 3. 数据要求

MySQL 保存页面、修订、元数据、评论、统计和搜索控制面；MongoDB 保存 BlogPage 的正式正文及历史快照；MinIO 保存图片、文档等对象；Redis 保存缓存、计数器和 Celery broker/backend；Elasticsearch 保存搜索和日志索引。`BlogPage.mongo_content_id` 是受保护引用，正文、草稿、revision pointer 不得因搜索故障删除。

## 4. 生命周期要求

开发者必须使用 Wagtail 的 revision/publish/unpublish/delete API。`BlogPage.save()` 负责 Mongo 正文持久化，`publish()`/`unpublish()`/`delete()` 与 `apps/search/signals.py` 共同产生搜索事件。搜索同步最终一致；事件重复、Worker 重启、ES 暂时不可用都必须可重试。

## 5. 接口与安全要求

公开读接口不得暴露未发布页面、Mongo ID、内部索引名、凭据或原始异常。评论等写接口必须认证并校验 CSRF、频率和对象权限。所有配置来自 `wagtailblog3/settings/.env.test|production`，禁止提交密钥。

## 6. 验收标准

变更至少执行 `python manage.py check`、受影响测试、`git diff --check`；模型变更增加 `makemigrations --check --dry-run` 和 `migrate --plan`。涉及浏览器的页面、后台、搜索分页和静态资源必须用 Playwright 验收，产物写入 `output/playwright/`。
