# WagtailBlog3 概要设计说明书

## 1. 分层与依赖

`wagtailblog3/settings/` 负责环境、数据库、缓存、Celery、搜索连接和日志；`apps/*/models.py` 定义领域模型和 Wagtail Page；`views.py` 只负责请求编排；`services/` 承载查询、缓存、外部系统和批处理；`tasks.py` 是 Celery 入口；`management/commands/` 是人工运维入口；`templates/` 和 `static/` 是表现层。

## 2. 请求路径

`wagtailblog3/urls.py` 先匹配 Django/Wagtail admin、documents、test-search、feed、comments、blog、archive、search，再由 `path("", include(wagtail_urls))` 服务页面。新增 URL 必须放在 Wagtail 通配路由之前，并在对应 app 的 `urls.py` 注册。

## 3. 内容写入路径

Wagtail 编辑请求进入 `BlogPageForm`；表单从 Mongo 恢复正文后校验 StreamField；`BlogPage.save()` 通过 `MongoManager` 写正式内容并更新 `mongo_content_id`，MySQL 保存页面指针和元数据。发布后搜索 signal 在同一事务记录 `ContentSearchState`/`ContentSearchOutbox`，提交后唤醒 maintenance 队列。

## 4. 搜索路径

前台 `search/views.py` 调用 `core.perform_search()`。独立内容搜索由 `services/content_query.py` 读取 serving alias，按页面公开状态二次过滤并补高亮；`federated_query.py` 合并内容索引和 Wagtail 页面结果。`services/cursor.py` 负责签名游标；`suggestions.py` 负责热门词和标题建议。

## 5. 异步与外部依赖

`celery_app.py` 加载任务；`settings/database.py` 将内容搜索任务固定到 `maintenance` 队列。Beat 调度 pending/过期 Delivery、日志索引补偿、分析清理。Mongo、ES、MinIO、Redis 任一不可用时，业务层必须返回受控错误或进入重试，不得在请求中静默丢数据。

## 6. 设计约束

不得在 signal 中直接写 Elasticsearch；不得绕过 Wagtail Page API 改 live/revision；不得将生产凭据写入代码；不得用通配符删除索引或 Mongo 集合。详细操作以 04、05、09-12 文档为准。
