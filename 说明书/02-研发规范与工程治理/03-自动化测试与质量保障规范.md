# 自动化测试与质量保障规范

## 1. 规范定位与测试体系总览

本规范为 WagtailBlog3 项目的质量保障基准，统一约束单元测试、集成测试、异步任务测试以及基于 Playwright 的端到端浏览器验收测试。所有新功能研发、缺陷修复及依赖升级均须遵循本规范设定的质量门禁。

### 1.1 核心质量原则
- **分层测试金字塔**：优先使用轻量级、无状态的单元测试进行快速验证，核心持久化与业务流使用数据库集成测试，关键用户路径与后台操作使用 Playwright 验收。
- **环境绝对隔离**：所有自动化测试只能在 WSL2 测试环境（`WAGTAILBLOG_ENV=test`）中运行，严禁连接或指向生产 MySQL、MongoDB、Redis、MinIO 或 Elasticsearch。
- **外部依赖 Mock 化**：涉及第三方外部服务（如 DeepSeek LLM API、外部邮件服务器、远程 CDN）时必须进行 Mock 拦截，禁止在测试中产生外部网络调用与费用消耗。
- **禁止通过削弱断言掩盖缺陷**：测试失败时必须排查业务逻辑或数据契约根因，严禁随意删除断言、注销测试用例或放宽安全边界。

## 2. 测试工程目录结构与组织规范

项目已完成全面的测试目录工程化治理，消除应用根目录松散脚本，统一采用标准的 Python 测试包结构：

│   │       ├── test_markdown_import_*.py # Markdown 跨端导入全生命周期测试
│   │       ├── test_mongo_sync.py     # MongoDB 存储与页面同步测试
│   │       └── ...
│   ├── search/

│   │       └── ...
│   ├── archive/
│   │   └── tests/                     # 归档与历史版本测试包
│   │       ├── __init__.py

## 3. 测试分类与编写规范

### 3.1 单元测试（Unit Tests）
- **基类选择**：继承 `django.test.SimpleTestCase`。
- **应用范围**：工具函数、表单校验器、模板标签（Template Tags）、DTO 数据类、AI 提示词构造器、正则匹配等纯逻辑计算。
- **性能要求**：执行时禁止访问数据库，单用例执行时间应小于 10ms。

### 3.2 数据库集成测试（Integration Tests）
- **基类选择**：继承 `django.test.TestCase`。
- **应用范围**：Wagtail Page 发布/草稿生命周期、Snippet 数据存取、MongoDB 正文同步、自定义模型查询集。
- **事务与清理**：利用 Django 自动事务包裹机制，每个用例执行完毕后自动回滚，确保测试间状态互不污染。
- **提速建议**：命令行增加 `--keepdb` 选项复用已初始化的测试数据库，避免重复跑迁移。

### 3.3 异步任务与队列测试（Async & Celery Tests）
- **基类选择**：继承 `django.test.TransactionTestCase`。
- **应用范围**：Outbox 扫描分发、Celery 异步 Worker 消费、Elasticsearch 批量索引构建、失败补偿重试机制。
- **注意要点**：由于涉及异步线程或进程对数据库 commit 状态的可见性，必须真实提交事务，在 `tearDown` 中显式清理测试数据。

### 3.4 浏览器端到端与 UI 验收（Playwright E2E Tests）
- **工具链**：Playwright MCP、Playwright CLI 及自动化脚本。
- **视口标准**：必须同时覆盖桌面端（1280×800）与移动端（375×667）。
- **产物存放规范（强制）**：
  - 所有测试截图、Trace 链路追踪文件、录像、PDF 导出及 HTML 报告，**必须统一存放于 `output/playwright/` 目录**（如 `output/playwright/<task-name>/`）。
  - 该目录受 `.gitignore` 保护，严禁将调试产物提交至 Git 仓库或同步至生产机器。

## 4. 常用测试执行命令与速查矩阵

测试命令必须在 WSL2 测试环境（`192.168.20.5`）下的 `wagtailblog-test` Conda 环境中执行：

| 测试场景 | 推荐命令 | 作用说明 |
|---|---|---|
| **全系统静态检查** | `python manage.py check` | 核验 Django/Wagtail 配置与模型定义 |
| **应用快速回归** | `python manage.py test blog search archive --keepdb` | 执行三大核心应用全部用例，复用数据库 |
| **AI 元数据专项** | `python manage.py test blog.tests.test_ai_metadata --keepdb` | 验证 DeepSeek 提示词解析与异常保护 |
| **搜索异步管道** | `python manage.py test search.tests.test_search_async --keepdb` | 验证 Outbox 投递与 Celery 异步通道 |
| **Markdown 导入专项** | `python manage.py test blog.tests.test_markdown_import_cors --keepdb` | 验证跨域预检、Token 认证与草稿保存 |
| **全局跨应用测试** | `python manage.py test wagtailblog3.tests --keepdb` | 验证跨应用中间件与核心配置契约 |
| **语法静态编译** | `python -m compileall -q wagtailblog3` | 快速核查全工程 Python 语法完整性 |

## 5. 本地与 CI/CD 质量流水线

### 5.1 本地 Pre-Commit 门禁
项目根目录配置了 `.pre-commit-config.yaml`，在 WSL2 中执行 Git 提交时自动触发：
1. `check-added-large-files`：拦截大文件误提交。
2. `check-merge-conflict`：检测未解决的 Git 冲突标记。
3. `django-check`：调用测试环境自动执行 `manage.py check`，配置错误将直接中断提交。

### 5.2 GitHub Actions 持续集成（CI）
在 `.github/workflows/django-ci.yml` 中定义自动化质量流水线：
- **触发条件**：推送到 `main` 分支或向 `main` 发起 Pull Request 时自动运行。
- **环境矩阵**：Python 3.13 + MySQL 8.4。
- **核验步骤**：自动安装 `requirements.txt`（严格锁定 Wagtail 8.0、Django 5.2.8），执行静态代码检查并跑通基础健康测试。

## 6. 测试红线与安全须知

1. **红线一：严禁测试生产数据**：不得以排查生产问题为由在生产数据库运行 `test` 指令，测试框架会触发清库重建，造成灾难性数据丢失。
2. **红线二：保护 MongoDB 正文**：本地测试涉及真实 Mongo 连接时，必须使用专门的测试库名（如 `wagtailblog_test`），严禁与开发库甚至生产库混用。
3. **红线三：测试产物零泄露**：生成的各类诊断文件（图片、视频、json）统一存放在 `output/` 临时目录下，不得将含有业务草稿的测试数据上传至公开仓库。
