## 0. 执行约束与责任

Gemini 负责每阶段代码和定向测试，Sol 按本计划逐门禁审核，Grok 在关键跨库/并发/恢复节点做对抗式复核。Windows 和 WSL2 共享 `.git`，同一时刻只在一端进行 Git 写操作。新文件责任：`wagtailblog3/apps/external_content/` 为通用正文内核；`wagtailblog3/apps/guides/` 与 `templates/guides/`、`static/guides/` 为业务；`wagtailblog3/apps/search/`、`templates/search/`、`static/search/` 为搜索集成；`settings/base.py`、主导航模板及相关测试只在对应阶段改动。开发者不得撤销其他协作者编辑，阶段交接时核对未提交工作树。

每阶段交付代码差异、实际触及文件、迁移文件、测试命令及输出摘要、残余风险。发现当前 Wagtail 8.0 Action 或现有 Blog 契约与设计不符，先反馈并修订方案，不以猜测绕开。所有新增/修改运行时代码写准确中文注释、docstring 和 Python 类型标注。每个通过审核的功能阶段在本地分支使用中文 Conventional Commit，例如 `feat(guides): 建立专题指南页面与编辑块`；Git 写操作由主控统一执行，避免 Windows/WSL2 并发写 `.git`。
