# 专题指南与正文外置分步实施计划

> 状态：研发计划，尚未实施。业务契约见《11-专题指南页面需求与详细设计说明书》，存储和生命周期权威见两份 `10-Wagtail Page正文外置通用协议` 文档。当前已获授权创建本地分支，并在每个完成且通过审核的功能阶段提交本地 Git；禁止推送 GitHub 或对生产环境执行变更。

## 0. 执行约束与责任

Gemini 负责每阶段代码和定向测试，Sol 按本计划逐门禁审核，Grok 在关键跨库/并发/恢复节点做对抗式复核。Windows 和 WSL2 共享 `.git`，同一时刻只在一端进行 Git 写操作。新文件责任：`wagtailblog3/apps/external_content/` 为通用正文内核；`wagtailblog3/apps/guides/` 与 `templates/guides/`、`static/guides/` 为业务；`wagtailblog3/apps/search/`、`templates/search/`、`static/search/` 为搜索集成；`settings/base.py`、主导航模板及相关测试只在对应阶段改动。开发者不得撤销其他协作者编辑，阶段交接时核对未提交工作树。

每阶段交付代码差异、实际触及文件、迁移文件、测试命令及输出摘要、残余风险。发现当前 Wagtail 8.0 Action 或现有 Blog 契约与设计不符，先反馈并修订方案，不以猜测绕开。所有新增/修改运行时代码写准确中文注释、docstring 和 Python 类型标注。每个通过审核的功能阶段在本地分支使用中文 Conventional Commit，例如 `feat(guides): 建立专题指南页面与编辑块`；Git 写操作由主控统一执行，避免 Windows/WSL2 并发写 `.git`。

## 2. 跨库与索引实施顺序

### G0 只读核查记录（2026-09-29）

| 已核查入口 | 代码事实 | 对 G1/G2 的约束 |
|---|---|---|
| `blog/models.py:978–1029`；Wagtail `models/pages.py:1004,1057–1074` | 现有 Blog 的 `serializable_data()` 直接写 Mongo；Wagtail `save_revision()` 调用该方法且支持 `overwrite_revision`。 | 新 mixin 的普通序列化必须纯读，只有显式 `prepare_revision` 写入；已被审批/发布引用的 Revision 禁止覆盖。 |
| Wagtail `admin/views/pages/create.py:265–280,320–341`；`edit.py:686–711` | 创建页先 `add_child` 取得真实主键，再保存 Revision；后台编辑可直接执行 `PublishPageRevisionAction`。 | 无主键页面不能生成 Mongo 版本；只覆盖子类 `publish()` 不足以保护后台发布。 |
| Wagtail `actions/publish_revision.py:56–58,106–175`；`publish_page_revision.py:46–57` | Action 构造时即把 Revision 还原为对象；原生发布改变 live 后发信号，再更新 Alias，整个路径没有可直接依赖的外层原子事务。 | G2 必须核定 Action 调用层、信号和 Alias 的共同事务边界；G1 不开放真实 Guide 发布。 |
| `blog/models.py:1207–1325`；`mongo.py:89–127` | Blog 仍有旧可变正文兼容写入，Mongo 异常有仅记录日志的分支；旧 MongoManager 初始化会连接并操作索引。 | 新仓储失败关闭；registry/checks 不构造 MongoManager，不从 Blog 复制异常降级。 |
| Wagtail `models/revisions.py:331–345`；`settings/database.py:746,845,892` | 历史还原含 `check_fks/strict_fks` 参数；默认搜索后端与附加后端的自动更新配置不同。 | mixin 保留反序列化参数签名；G0/G5 继续验证默认索引旁路，不假定 Outbox 已是唯一写入口。 |

以上是本地源码只读证据，不代表 G1/G2 代码或生命周期测试已经通过。G0 剩余项：在隔离测试环境复现草稿 overwrite、后台 Action 事务/信号、Alias 同步和默认搜索自动索引；形成测试证据后才能关闭 G0 门禁。

1. 先落应用、迁移、只读/写入 codec 和旧版本解码器；启动检查在错误策略下拒绝服务。新指南 Page 只在测试数据中创建，不触碰存量 Blog、Home、Portfolio 正文。
2. 完成 Mongo 不可变版本写入和 MySQL Revision/Manifest 提交，验证事务失败留下的 Mongo 孤儿不可见且可安全延迟复核；不以跨库“同时提交”的假设设计补偿。
3. 把正式正文指针从搜索 producer 开关解耦，再扩展搜索 Outbox。发布/下架事务先保证 MySQL Page/Revision/状态一致；ES 只经 Outbox 最终收敛，tombstone 拒绝旧 UPSERT。
4. 指南初次公开前，在隔离环境演练 MySQL、Mongo 和 ES 的同点恢复；若 MySQL 回退到较旧状态，以新 epoch 和新物理索引重建并原子切换读 alias。禁止直接在旧 ES 索引续投低代次事件。

## 3. 可执行验收矩阵

| 维度 | 必验情形 | 通过依据 |
|---|---|---|
| 存储 | Index 原生；Guide 仅 body 外置；专用测试 Page 双外置 + 一原生；未知字段/codec；跨页/哈希损坏 | MySQL 不存正文 payload；Manifest 精确；非法读取失败关闭 |
