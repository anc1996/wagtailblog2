# WagtailBlog3 数据库设计说明书

## 1. 数据库职责

### MySQL

Django/Wagtail 核心表保存 `wagtailcore_page`、revision、用户、权限、站点和集合。Blog 应用迁移位于 `apps/blog/migrations/0001-0023`，覆盖 `BlogPage`、`BlogIndexPage`、`BlogCategory`、`Author`、图片、标签、浏览量、反应、Feed 和互动统计。Comments、Archive、Home、Portfolio、Observability、Search 各应用各自维护迁移。

### MongoDB

`wagtailblog3/mongo.py` 的 `MongoManager` 负责正式正文、历史大文本和删除；`wagtailblog3/mongodb.py` 的 `MongoDBStreamFieldAdapter` 负责 StreamField 与 Mongo JSON 转换。Mongo 文档 ID 写入 `BlogPage.mongo_content_id`，不能手工改成不存在的 ID。

## 2. 搜索控制面表

| 模型 | 主键/唯一约束 | 作用 |
|---|---|---|
| `ContentSearchState` | `page_id` 主键 | 当前公开状态、版本、hash、Mongo 指针 |
| `ContentSearchOutbox` | `event_id`；`page_id+content_version` 唯一 | 事务事实事件 |
| `ContentSearchTarget` | `target_id` 唯一 | settings connection、物理索引、角色 |
| `ContentSearchDelivery` | `event+target` 唯一 | 投递租约、重试、死信 |
| `SearchIndexBuild` | `build_id` 唯一 | 回填 checkpoint、追平、门禁状态 |
| `ContentSearchScopeJob` | 见 `search/models.py` | 站点/权限范围重算 |

迁移顺序以 `apps/search/migrations/0001-0005` 为准。修改模型必须新增迁移，不得编辑已应用迁移。

## 3. 数据保护

正文、草稿、revision、Mongo 指针、评论和生产日志属于受保护数据。备份/恢复遵循 12；查询只返回必要字段；错误字段不得保存正文或密码。清理浏览量和日志只能使用已审计 management command，并先确认保留期。
