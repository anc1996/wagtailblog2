# WagtailBlog3 部署与运维手册

## 1. 环境与目录

测试：`/mnt/f/openclaw/workspace/wagtail/wagtailblog2` + `/root/anaconda3/envs/wagtailblog-test`；生产：`/home/source/Django/wagtail/wagtailblog3` + `/root/anaconda3/envs/wagtailblog`。配置仅使用 `wagtailblog3/settings/.env.test` 或 `.env.production`，由 `WAGTAILBLOG_ENV` 选择。

## 2. 服务清单

| unit | 作用 | 代码/配置变化时 |
|---|---|---|
| `wagtailblog3.service` | uWSGI/Django | 重启网站并验首页/后台 |
| `wagtailblog3-celery-maintenance.service` | 内容搜索 Delivery、维护任务 | 重启 Worker，验 maintenance 队列 |
| `wagtailblog3-celery-beat.service` | 调度与失败补偿 | 重启 Beat，验 schedule |
| `wagtailblog3-filebeat.service` | 日志采集 | 日志格式/ES 变化时重启 |

服务路径、socket、端口以 `systemctl.md` 和现场 unit 为准，不能凭本文旧值操作。

## 3. 标准发布

WSL2 核对 `git status --short --branch`、SHA、远程和环境；执行 `manage.py check`、受影响测试、迁移计划和 `git diff --check`；在 `main` 提交推送；生产 `fetch` 后只允许 `merge --ff-only` 到已验证 SHA；按依赖顺序 daemon-reload/重启并验收四个服务。

## 4. 常见故障

- 搜索无结果：先查 serving alias、Target enabled/role、`search_sync_status`，再查 Delivery dead/retry；不要先删索引。
- 搜索延迟：查 Beat、maintenance Worker、Redis、租约和 ES bulk 错误。
- 后台正文为空：查 `mongo_content_id`、Mongo 连通性和 `BlogPageForm` hydration；不得保存空正文覆盖。
- 日志不入 ES：查 Filebeat、observability outbox 和 ES 日志连接；项目服务本身可先保持运行。
