**版本: 2.0 (架构重构生产级规范)** **日期: 2025-06-13** ---

## **1. 部署架构概览 (Deployment Architecture Overview)**

WagtailBlog3 在生产环境（Production）下采用**全组件解耦与多维异构的拓扑架构**。为了换取单机极致的并发吞吐能力与内存绝缘安全性，系统摒弃了传统的单体关系型数据库承载大文本的模式，演进为分层过滤、多轨驱动的拓扑集群。

### **1.1 数据与流量处理拓扑图**

```text
[ 外部访客流量 ] 
       │ (HTTPS / Port 443)
       ▼
  [ Nginx 集群 ] ────(静态静态/媒体资源直接拦截分发)──► [ 物理磁盘 / OSS ]
       │
       ▼ (Unix Domain Socket: wagtailblog3.sock)
 [ uWSGI Master 进程树 ] 
       │ (Conda 虚拟环境强锁定)
       ▼
 [ Django / Wagtail 逻辑核心 ] 
       │
       ├─► [ MySQL 8.0 ] (骨架路由树、高频关联元数据事务)
       ├─► [ MongoDB 5.0+ ] (Body 大文本负载 BSON 树、无限堆叠草稿快照)
       ├─► [ Elasticsearch 8 ] (L1 倒排分词高亮召回大脑)
       └─► [ Redis 6.0 ] (L2 检索结果主键缓存、Celery 异步缓冲队列池)

```

| 绝对物理路径                                                 | 所有者:组   | 权限  | 架构目的 / 包含组件                                |
| ------------------------------------------------------------ | ----------- | ----- | -------------------------------------------------- |

| `/home/source/Django/wagtail/wagtailblog3/static/`           | `root:root` | `755` | 静态资源收集汇聚区（Nginx 直接拦截）               |

| `/root/anaconda3/envs/wagtailblog/`                          | `root:root` | `755` | 绝缘的 Conda 虚拟环境隔离区                        |

## **3. 基础依赖组件生产级配置 (Infrastructure Configuration)**

### **3.1 MySQL 8.0 核心存储配置**

修改 `/etc/mysql/mysql.conf.d/mysqld.cnf`，优化宽表剥离后的索引扫描效率：

```ini
[mysqld]
# 字符集强制归一化，坚决防止 Emoji 评论引发写入崩溃
character-set-server = utf8mb4
collation-server = utf8mb4_unicode_ci

# 针对轻量骨架主表，大幅提升索引页缓存池
innodb_buffer_pool_size = 2G
innodb_log_file_size = 512M
innodb_flush_log_at_trx_commit = 2
innodb_lock_wait_timeout = 50

```

### **3.2 MongoDB 5.0+ 非结构化集合配置**

由于 MongoDB 承载了全站庞大的 `body` BSON 载荷，必须修改 `/etc/mongod.conf` 以保证存储吞吐：

```yaml
storage:
  dbPath: /var/lib/mongodb
  journal:
    enabled: true
  wiredTiger:
    engineConfig:
      # 限制缓存大小，预留给 ES8 和 Django 足够的内存运行空间
      cacheSizeGB: 2
net:
  port: 27017
  bindIp: 127.0.0.1
security:
  authorization: enabled

```

### **3.3 Elasticsearch 8 分词检索集群配置**

编辑 `/etc/elasticsearch/elasticsearch.yml` 与虚拟机参数 `/etc/elasticsearch/jvm.options`：

```yaml
# elasticsearch.yml
cluster.name: wagtail-search-cluster
node.name: node-1
network.host: 127.0.0.1
http.port: 9200
xpack.security.enabled: false  # 单机极速无密通信，生产环境建议内网隔离

```

```ini
# jvm.options
# 强行锁定物理内存，坚决防止 JVM 频繁引发 OOM 崩溃
-Xms2g
-Xmx2g

```

### **3.4 Redis 6.x 高速键值缓存配置**

修改 `/etc/redis/redis.conf`，确保 L2 主键缓存与 Celery 缓冲队列绝缘安全：

```ini
bind 127.0.0.1
port 6379
protected-mode yes
requirepass YourHighSecureRedisPassword

# 配置最大内存淘汰策略，防止主键缓存塞满引发异步任务熔断
maxmemory 1gb
maxmemory-policy allkeys-lru
appendonly yes
appendfsync everysec

```

## **5. Systemd 守护进程生命周期托管 (Systemd Automation)**

全面废除脆弱的外部自启脚本。通过操作系统内核级状态机管理器，实现进程级绝缘隔离与多业务平滑重启。

### **5.1 核心 Web 服务: `wagtailblog3.service**`

```bash
sudo nano /etc/systemd/system/wagtailblog3.service

```

填入以下经过微观调优的单元配置文件：

```ini
[Unit]
Description=uWSGI High-Performance Instance for WagtailBlog3
After=network.target mysql.service mongodb.service elasticsearch.service
Wants=mysql.service mongodb.service elasticsearch.service

[Service]
User=root
Group=root
WorkingDirectory=/home/source/Django/wagtail/wagtailblog3

# 核心防线：硬编码注入绝对路径 PATH 环境变量，锁定 Conda 解释器，根治环境漂移
Environment="PATH=/root/anaconda3/envs/wagtailblog/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin"
Environment="DJANGO_SETTINGS_MODULE=wagtailblog3.settings.production"

# 启动行为控制：指向 Conda 虚拟环境下的 uwsgi 核心。uwsgi.ini 内部已注释掉 daemonize
ExecStart=/root/anaconda3/envs/wagtailblog/bin/uwsgi --ini uwsgi.ini

# 进程熔断自愈策略：放弃不安全死循环，改用 failure 异常退出触发自愈
Restart=on-failure
RestartSec=5s

# 优雅重载控制 (Zero-Downtime Reload)
KillSignal=SIGQUIT
Type=notify
NotifyAccess=all

# 可观测性日志标准重定向
StandardOutput=syslog
StandardError=syslog
SyslogIdentifier=wagtailblog-uwsgi

[Install]
WantedBy=multi-user.target

```

### **5.2 异步队列 Worker 服务: `wagtailblog-celery.service**`

```bash
sudo nano /etc/systemd/system/wagtailblog-celery.service

```

```ini
[Unit]
Description=Celery High-Throughput Worker for WagtailBlog3
After=network.target redis.service mysql.service
Wants=redis.service

[Service]
User=root
Group=root
WorkingDirectory=/home/source/Django/wagtail/wagtailblog3
Environment="PATH=/root/anaconda3/envs/wagtailblog/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin"
Environment="DJANGO_SETTINGS_MODULE=wagtailblog3.settings.production"

# 限制并发子进程数，预留内存空间给 MongoDB 与 ES8
ExecStart=/root/anaconda3/envs/wagtailblog/bin/celery -A wagtailblog3 worker -l INFO --concurrency=2

Restart=on-failure
RestartSec=10s
KillSignal=SIGTERM

StandardOutput=syslog
StandardError=syslog
SyslogIdentifier=wagtailblog-celery

[Install]
WantedBy=multi-user.target

```

## **6. Nginx 高性能路由树配置 (Nginx Site Configuration)**

编辑 `/etc/nginx/sites-available/wagtailblog3` 并软链接至 `sites-enabled`：

```nginx
# 建立防穿透爬虫限流隔离区
limit_req_zone $binary_remote_addr zone=search_limit_per_ip:10m rate=10r/s;

server {
    listen 80;
    server_name yourdomain.com;
    return 301 https://$server_name$request_uri; # 强制全站安全 HTTPS 化
}

server {
    listen 443 ssl http2;
    server_name yourdomain.com;

    # SSL 物理证书锁死配置
    ssl_certificate /etc/letsencrypt/live/yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/yourdomain.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    # 全局长连接调优
    keepalive_timeout 70;
    client_max_body_size 50M; # 放宽多媒体块上传限制

    # 静态收集区资源直接物理拦截，实现零 Django 负载分发
    location /static/ {
        alias /home/source/Django/wagtail/wagtailblog3/static/;
        expires 30d;
        access_log off;
        add_header Cache-Control "public, no-transform";
    }

    # 多媒体资源大文件拦截
    location /media/ {
        alias /home/source/Django/wagtail/wagtailblog3/media/;
        expires 30d;
        access_log off;
    }

    # 针对异步检索 AJAX 接口施加动态流控限流，保护分布式连接池
    location /search/ {
        limit_req zone=search_limit_per_ip burst=15 nodelay;
        include uwsgi_params;
        uwsgi_pass unix:/home/source/Django/wagtail/wagtailblog3/wagtailblog3.sock;
        uwsgi_read_timeout 60;
    }

    # 统一动态请求下推至 Unix 套接字
    location / {
        include uwsgi_params;
        uwsgi_pass unix:/home/source/Django/wagtail/wagtailblog3/wagtailblog3.sock;
        uwsgi_read_timeout 120;
        uwsgi_send_timeout 120;
    }
}

```

## **8. 自动化运维流与故障排查矩阵 (Runbook)**

### **8.1 零停机零 502 错误代码平滑更新 (Zero-Downtime Deployment)**

当代码库发生更迭（`git pull`）后，严禁粗暴 Kill 进程。利用 Systemd 向 uWSGI Master 派发标准 `SIGQUIT` 信号，工作者进程在完美处理完当前的访客请求后平滑释放内存套接字并自动满血重载，实现前台零感知跃迁：

```bash
sudo systemctl restart wagtailblog3

```

### **8.2 核心可观测性排错命令集**

应用层日志已完美收拢至内核系统层，排错不再需要到处捞取 `.log` 文件：

```bash
# 查看统一 Web 进程池的高精滚动日志流
sudo journalctl -u wagtailblog3.service -f

# 精准过滤特定错误载荷日志
sudo journalctl -u wagtailblog3.service --since "1 hour ago" | grep -iE "error|exception|500"

# 查看异步 Celery Worker 的派发落地日志
sudo journalctl -u wagtailblog-celery.service -n 50 --no-pager

```

### **8.3 异构数据库关联断裂自愈验证**

若发生分布式网络分区，导致 MySQL 行中的 `mongo_content_id` 指针在 MongoDB 正式集合中找不到目标数据：

* **运维策略**：此时系统底层的 `getValue` 级联防御补丁会自动拦截崩溃。你会在日志中观测到 `StreamField 反序列化降级` 或 `ValueError`。系统会将页面降级渲染为空，坚决阻断 500 恶性崩溃。此时应立刻恢复 MongoDB 对齐备份包。
