## 2. 实施目标

### 2.1 最终目标

完成后，前台公开搜索应具备以下能力：

1. 只搜索已经发布、允许公开访问的页面。
2. MongoDB 草稿和历史 Revision 正文永不进入公开搜索结果、建议或高亮。
3. 已发布页面保存新草稿时，搜索继续展示上一次正式发布内容。
4. 发布、取消发布、访问限制变化和删除最终可靠同步到 Elasticsearch。
5. Worker 崩溃、Celery 重投、ES 短暂故障不会丢事件或让旧正文覆盖新正文。
6. 全量重建期间前台搜索不停机，内容发布不停机，增量更新不丢失。
7. 新旧索引能够影子对比、原子切换和快速回滚。
8. Elasticsearch 只保留检索所需字段，MongoDB 继续作为正式正文和草稿正文的权威存储。
9. 当前 8 GiB 主机阶段控制资源占用；规模增长触发阈值前迁移到独立 ES 节点或集群。

### 2.2 非目标

本轮实施不包含：

- 修改 `markdown_block` key 或 Markdown 存储格式。
- 迁移、删除或批量修复 MongoDB 正文和 Revision 快照。
- 用 Mongo regex、Mongo `$text` 或 MySQL `LIKE` 替代公开全文检索。
- 引入向量搜索、语义问答或大模型检索。
- 重写 Wagtail 页面树、权限系统或 Revision 模型。
- 新增只消费 `default` 或 `email` 队列的 Worker。
- 未压测前承诺千万级固定吞吐、延迟或硬件容量。

## 3. 当前实现基线

实施前以代码再次核实，当前已确认的基线如下。

### 3.1 搜索入口

- `wagtailblog3/apps/search/core.py`：查询清理、原生 ES DSL、Wagtail 搜索回退、API 格式化和搜索建议。
- `wagtailblog3/apps/search/views.py`：HTML 页面、异步结果片段和兼容 AJAX 响应。
- `wagtailblog3/apps/search/api.py`：公开搜索 API 和建议 API。
- `wagtailblog3/apps/search/cache.py`：搜索结果缓存。
- `wagtailblog3/apps/search/test_search_async.py`：当前主要覆盖视图契约，没有数据库、Mongo、ES 发布链路集成测试。

原生 ES DSL 当前只过滤 `live_filter=True`；QuerySet 路径使用 `.live().public()`。原生 DSL 不能独立证明访问受限页面不会泄漏，这是第一个必须关闭的正确性缺口。

### 3.2 正文和草稿

- `BlogPage.serializable_data()` 把 Revision 草稿正文写入 MongoDB 草稿集合，并在 MySQL Revision 中只保存 `mongo_draft_pointer`。
- `BlogPage.get_content_from_mongodb()` 和 `body_text` 从正式 `blog_content` 集合读取搜索正文。
- `BlogPage.save()` 在特定全量保存路径写正式 Mongo 正文，随后清空 MySQL `body`。
- 当前代码注释表达了正式正文和草稿正文分离意图，但必须用真实 Wagtail 保存草稿、发布和重新发布集成测试证明该边界。

### 3.3 发布生命周期

测试环境实际安装 Wagtail 7.4.2。源码核实结果：

- `Revision.publish()` 调用具体页面对象的 `publish()`。
- Wagtail 发布动作先保存 Page，再发送 `page_published`。
- Wagtail 取消发布动作先保存 Page，再发送 `page_unpublished`。
- 上述动作自身没有提供可依赖的项目级外层 `transaction.atomic()` 保证。

因此不能只在 signal 中创建 Outbox 后声称它与页面状态原子提交。实施时必须为 `BlogPage.publish()`、`BlogPage.unpublish()` 和删除链路建立明确的外层事务，并用 `TransactionTestCase` 验证回滚行为。

### 3.4 Celery 与运维

- 已有 `maintenance` 队列、Worker 和 Beat。
- 当前 Celery 已配置 `acks_late=True`、`reject_on_worker_lost=True`、prefetch 1。
- `observability.LogIndexSyncJob` 已使用“事务内 Outbox、`on_commit()` 唤醒、Beat 补偿、死信”模式。
- 内容搜索可以复用该模式的经验和日志规范，但不能直接复用单任务模型；内容搜索还需要页面单调版本、按索引目标 Delivery、租约和在线重建状态。
- 本方案不新增 Worker 服务或队列，但会改变 maintenance Worker 和 Beat 职责，因此实现阶段必须同步更新 `systemctl.md`。

## 4. 不可破坏的实施约束

所有工作包必须遵守：

1. MySQL、MongoDB 是主数据；ES 是可重建读模型。
2. 搜索构建器只读取 Mongo 正式正文，不读取 `blog_page_revision_bodies`。
3. 任何 Mongo 临时失败都不能用空正文覆盖 ES 现有文档。
4. 任何旧事件都不能覆盖高版本文档或复活 tombstone。
5. 公开搜索结果在模板、API、缓存、建议和高亮层使用相同公开边界。
6. 安全过滤必须在返回标题、URL、高亮片段之前完成，不能只在模板中隐藏。
7. 生产修复命令默认只读；写操作必须要求 `--confirm`，并输出目标环境、索引和预计影响。
8. 新功能先以 feature flag 关闭方式发布，再单独启用。
9. 每个工作包只处理本阶段目标，不顺带重构 Mongo 正文结构、Wagtail 页面模型或日志系统。
10. Playwright 产物统一写入 `output/playwright/search-architecture/<work-package>/`。

## 7. 工作包 WP1：当前搜索正确性修复（推荐模型：`gpt-5.6-terra`；推理强度：高）

### 7.1 目标

在建立独立索引前，先让当前 `/zh-hans/search/`、结果 API、建议和缓存遵守统一公开边界，并修复已确认的低风险浪费。

### 7.2 预计修改

- `wagtailblog3/apps/search/core.py`
- `wagtailblog3/apps/search/views.py`
- `wagtailblog3/apps/search/api.py`
- `wagtailblog3/apps/search/cache.py`
- `wagtailblog3/apps/blog/models.py`
- 搜索测试
- `说明书/搜索流程.md`

### 7.3 任务清单

1. 给当前原生 ES DSL 增加公开范围防护。
2. 优先评估让公开入口使用 `Page.objects.live().public().search()`；只有证明结果质量和性能不能满足时，才保留原生 DSL 并实现等价公开过滤。
3. 即使使用独立公开索引，也对返回页 ID 做 MySQL `.live().public()` 防御性复核，且必须在格式化标题、URL和高亮之前完成。
4. 为访问限制变更增加缓存失效；缓存 key 增加搜索实现版本，避免切换索引后读到旧结果。
5. 修复 `_count` 和当前页 `_search` 的重复精确计数。
6. 当前页查询设置合理的 `track_total_hits`，不对每次请求重复做昂贵精确统计。
7. 为超过 10,000 结果窗口返回明确限制，不伪装成可以任意深翻页。
8. 在确认没有 `.autocomplete()` 调用后移除 `AutocompleteField('title')`。
9. 更新搜索流程文档中关于真实降级、深分页和公开边界的说明。

### 7.4 安全要求

- 不得先把 ES 高亮或标题写入响应，再在模板层过滤受限页面。
- 搜索缓存不得缓存未经 `.public()` 复核的结果。
- 建议 API 不得返回未发布或受限页面标题。
- ES 不可用时返回明确不可用状态，不能用空数组冒充“0 条结果”。

### 7.5 测试

- 未发布页面在 HTML、JSON API、AJAX 和建议中均不可见。
- 受直接限制和祖先页面限制的页面均不可见。
- 已发布页面的新草稿关键词不可搜索。
- 相同查询在缓存命中和未命中时公开边界一致。
- ES 失败返回稳定错误契约。
- 删除 `AutocompleteField` 后现有建议结果不变。
- Playwright 验证桌面和移动搜索页，无溢出、遮挡、JS 错误和失败请求。

### 7.6 生产影响和确认点

代码发布需要重启 Django/uWSGI。移除 `AutocompleteField` 只有重建 Wagtail ES 索引后才会释放空间；生产索引重建属于独立写操作，必须单独确认。可先发布兼容代码，暂不重建。

- 不涉及 Mongo 或 MySQL 内容回滚。

## 10. 工作包 WP3B：发布事件和页面单调版本（推荐模型：`gpt-5.6-terra`；推理强度：高）

### 10.1 目标

把首次发布、重新发布、取消发布和删除可靠记录为 MySQL Outbox；`on_commit()` 只唤醒任务。

### 10.2 事务实现

计划采用：

1. 覆盖 `BlogPage.publish()`，在外层 `transaction.atomic()` 中调用 Wagtail 原实现。
2. 覆盖 `BlogPage.unpublish()`，同样建立外层事务。
3. 调整现有 `BlogPage.delete()`，在调用 `super().delete()` 前于同一 MySQL 事务写 tombstone 状态；不在本工作包重构 Mongo 删除语义。
4. `page_published` 和 `page_unpublished` receiver 只调用搜索同步服务，不直接调用 ES。
5. `transaction.on_commit()` 只投递 maintenance 唤醒任务；Celery 发送失败时保留 pending 事件，由 Beat 恢复。

不能假设后台 HTTP 请求、定时发布器或其他调用方已经包住事务；测试必须直接调用 Revision publish 和 Page unpublish 验证。

### 10.3 版本规则

- 在 `ContentSearchState` 行上 `select_for_update()`。
- 每次公开搜索状态变化递增 1。
- hash 只校验内容，不参与版本排序。
- 首次没有 State 时创建版本 1。
- 相同页面并发发布通过行锁串行生成不同版本。
- 删除后保留 State；以后即使复用相同 page_id 的异常旧事件，也不能回到低版本。

### 10.4 正式文档构建输入

事件生成时记录：

- `page_id`。
- 当前 `mongo_content_id`。
- `live` 和公开期望状态。
- 正式正文 hash。
- 操作和版本。

正文仍由 Worker 按最新 State 读取正式 Mongo 集合；Outbox 不保存正文，日志也不输出正文。

### 10.5 访问限制变化

`PageViewRestriction` 可能影响整个子树，不能在一个 signal 事务内为千万页面逐行创建事件。分两层处理：

1. 查询时始终执行 MySQL `.live().public()` 防御性复核，立即阻止受限内容返回。
2. restriction 变更写入范围重算请求，由 maintenance Worker 按 Page 主键游标分批生成页面版本和 tombstone/upsert。

范围重算未完成前允许 ES 暂时残留文档，但公开响应不得泄漏。需要新增范围任务模型时，优先复用 `SearchIndexBuild` checkpoint 结构或增加专门 `ContentSearchScopeJob`，不能把数百万 ID 塞入一个 JSONField。

## 11. 工作包 WP3C：租约消费者、重试和 tombstone（推荐模型：`gpt-5.6-terra`；推理强度：高）

### 11.1 目标

使用现有 maintenance Worker 以至少一次语义消费 Delivery，并保证任何崩溃窗口最终收敛。

### 11.2 消费流程

1. Beat 每 30 秒或经压测确定的间隔调用 dispatcher。
2. Dispatcher 只选择到期 Delivery ID，分批投递 maintenance 队列。
3. Worker 使用短事务、`select_for_update(skip_locked=True)` 领取 Delivery。
4. 写入 `processing`、`locked_by`、`lock_expires_at` 后立即提交事务。
5. 在事务外读取 State、MySQL 元数据和 Mongo 正式正文。
6. 构建规范化文档后再次核对 State 版本和 hash。
7. 使用 ES Bulk index、`version=content_version`、`version_type=external` 写目标物理索引。
8. ES 成功后在短事务中完成 Delivery；所有 required 目标完成后汇总 Outbox 状态。
9. 租约超时由 Beat 回收；长批次按需续租。

### 11.3 状态分类

| 情况 | 状态 |
| --- | --- |
| 相同版本、hash 和操作 | succeeded |
| ES 已有更高版本 | superseded |
| 事件版本低于当前 State | superseded |
| ES 429、5xx、超时 | retry |
| Mongo 临时不可用 | retry |
| live 页面正式正文永久缺失 | dead |
| mapping 400 或规范化程序错误 | dead |

退避使用指数增长和随机抖动。旧版本不进入 dead；单个 dead 不阻塞同页较新版本。

### 11.4 Tombstone

取消发布、删除和变为非公开状态时，向 ES index 一个轻量文档：

```json
{
  "page_id": 123,
  "content_version": 8,
  "searchable": false,
  "operation": "tombstone"
}
```

不得保留标题、简介、正文和高亮字段。公开查询强制 `searchable=true`。不直接 DELETE 的原因是 ES 默认只短期保留删除版本，迟到旧 upsert 可能在保留期后复活文档。

## 14. 工作包 WP4B：在线全量回填和增量双投递（推荐模型：`gpt-5.6-terra`；推理强度：高）

### 14.1 目标

在不停止搜索和发布的情况下完成新索引全量构建，并持续接收构建期间增量变化。

### 14.2 启动顺序

1. 创建新物理索引并验证 mapping。
2. 在 MySQL 注册 building Target。
3. 确认 consumer 每次领取时读取活动目标，不缓存旧目标列表。
4. 从注册成功后开始为新事件创建旧、新目标 Delivery。
5. 再启动全量回填。

不能先扫描再注册目标；否则扫描结束到增量启用之间存在漏写窗口。

### 14.3 回填命令

计划新增：

```text
search_rebuild_content_index
```

参数至少包括：

- `--target`
- `--batch-size`
- `--max-batch-bytes`
- `--resume-build`
- `--dry-run`
- `--confirm`

生产模式必须指定物理目标并二次确认，不接受 read alias 或通配符。

### 14.4 批处理

1. MySQL 按 Page 主键游标读取 live/public 页面。
2. 每批收集 `mongo_content_id`。
3. Mongo 使用 `_id in [...]` 批量读取正式正文。
4. 在内存构建 ID 到正文映射。
5. 使用统一 document builder 生成文档。
6. ES Bulk 携带 external version 写入。
7. 每批提交 checkpoint、成功数、缺失数和失败分类。
8. 进程崩溃后从 checkpoint 恢复。

批次同时受文档数和字节数限制。从 200-1,000 篇和较小字节上限开始压测。

### 14.5 并发收敛

- 回填 V10、增量已有 V11：V10 version conflict 后归类 superseded。
- 回填先写 V10、增量后写 V11：最终为 V11。
- 扫描期间取消发布：V11 tombstone 覆盖 V10 正文。
- 扫描期间访问受限：查询时 MySQL guard 立即防泄漏，异步 tombstone 最终收敛。

不使用“最大 Outbox 自增 ID”作为唯一水位，因为自增分配顺序不等于事务提交顺序。

### 14.6 追平门禁

新索引进入 ready 前必须满足：

- checkpoint 覆盖最后 Page ID。
- 新目标没有 pending、processing、retry 或 dead。
- 租约超时为 0。
- oldest pending 连续两个周期低于阈值。
- State 与 ES 版本扫描无缺失、陈旧或错误复活。
- live/public 数量和分类分布符合预期。
- 影子查询质量和延迟达标。

### 14.7 回滚

回填失败时将 Build 标记 failed，停止给失败目标创建新 Delivery。旧 Wagtail 搜索和旧读别名继续服务。删除失败索引必须另行确认，不能作为自动清理。

## 15. 工作包 WP4C：影子查询、切换和观察期（推荐模型：`gpt-5.6-terra`；推理强度：高）

### 15.1 目标

在用户无感知情况下比较新旧结果，通过后切换前台搜索，并保留可快速回滚窗口。

### 15.2 影子模式

- 用户响应仍来自旧搜索。
- 后台以采样比例查询新索引。
- 只记录 query hash、结果 page_id、排序差异、延迟和错误分类。
- 不记录完整正文、用户身份或敏感查询原文。
- 影子请求必须设置并发、超时和熔断，不能拖慢主请求。

### 15.3 切换门禁

- WP4B 全部追平门禁通过。
- 评测集质量不低于旧索引。
- 新索引 P95/P99 达标。
- 公开边界、草稿隔离和高亮测试通过。
- 新旧差异均已分类。
- 测试环境完成别名切换和回滚演练。
- 生产 snapshot 和旧别名状态已记录。

### 15.4 切换

同一集群使用单次 aliases API 原子把 `content-read` 从旧内容索引切到新内容索引。注意：初次从 Wagtail 搜索切换到独立内容搜索还包含应用 query flag 切换，不仅是 ES alias。

切换后：

- 观察期继续双投递旧、新目标。
- 监控结果差异、错误率、延迟和 Delivery lag。
- 不立即删除旧索引。
- 达到观察门槛后才停止旧目标新 Delivery。

### 15.5 回滚

- query flag 切回旧实现。
- read alias 原子切回旧内容索引。
- 因观察期仍双投递，旧目标保持最新。
- 保留新索引和 Delivery 供分析，不自动删除。

## 16. 工作包 WP5：深分页和建议系统（推荐模型：`gpt-5.6-sol`；推理强度：中）

### 16.1 游标分页

- 使用 `search_after`。
- 排序包含稳定字段和唯一 `page_id` tie-breaker。
- 需要跨页一致性时使用短生命周期 PIT。
- 游标签名并绑定 query hash、筛选、排序、locale 和过期时间。

- 热门搜索词：Redis Sorted Set 或聚合表。

## 17. 工作包 WP6：独立 Elasticsearch 集群（推荐模型：`gpt-5.6-terra`；推理强度：高）

### 17.1 触发条件

任一条件出现即可启动，不必等待文章数阈值：

- heap 持续超过 75%。
- old GC 或长停顿增长。
- 搜索 P95 超过 200 ms 且查询优化无效。
- 主机 available memory 持续低于 1.5 GiB。
- swap 持续活动。
- 主分片接近 40-50 GiB。
- 无法容纳新旧双索引和 merge 空间。
- 搜索、Kibana 或日志查询影响网站请求。

### 17.2 迁移步骤

1. 根据真实索引大小、吞吐和压测确定节点、heap、磁盘和分片。
2. 配置 TLS、最小权限账号和 snapshot repository。
3. 新集群创建内部 read alias 和物理索引。
4. 在 MySQL 注册新集群 Target；连接 URL 和凭据只放环境配置。
5. 应用投影器同时向旧、新集群创建 Delivery；ES alias 不能跨集群。
6. 全量回填并追平新集群。
7. 影子查询。
8. 切换应用读取连接或稳定代理。
9. 观察期继续双集群写入。
10. 门禁通过后停止旧集群投递，保留回滚窗口。

### 17.3 生产影响

该阶段涉及新基础设施、环境变量、可能的防火墙和证书、服务重启及容量费用，必须形成独立部署方案，本文不能直接授权执行。

### 17.4 回滚

读取连接切回旧集群，观察期内继续向旧、新目标投递；新集群索引、snapshot 和失败 Delivery 保留供核对。停止或删除新集群资源必须由独立基础设施变更和确认流程处理。

## 22. 回滚总则

### 22.1 应用回滚

恢复上一已验证 commit。若旧代码不知道新表，保留表不影响运行。

### 22.2 搜索读取回滚

关闭 `CONTENT_SEARCH_QUERY_ENABLED`，或把 read alias 切回旧索引。读取回滚不删除新索引。

### 22.3 同步回滚

关闭 producer/consumer，保留 State、Outbox、Delivery 和 dead。不得把 pending 直接改 succeeded。

### 22.4 索引回滚

原子切回旧 alias，保留失败索引和构建报告。删除索引必须单独授权。

### 22.5 数据库回滚

只有 migration 已证明可逆且尚未承载必要审计数据时才考虑反向迁移。默认策略是保留新表、关闭功能，而不是删除事件。

### 22.6 Mongo 数据

搜索回滚不删除、不恢复、不批量修改 Mongo 正式正文、草稿、Revision pointer 或 `mongo_content_id`。
