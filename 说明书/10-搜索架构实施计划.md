# 搜索架构实施计划与实施记录规范

## 1. 当前代码工作包

WP1 生产者：`signals.py` + `services/outbox.py`；WP2 文档/Mongo/ES：`document.py`、`mongo.py`、`elasticsearch.py`；WP3 Delivery：`delivery.py`、`tasks.py`；WP4 重建/alias：`rebuild.py`、`alias.py`；WP5 查询体验：`content_query.py`、`cursor.py`、`suggestions.py`；WP6 观测/一致性/命令：`consistency.py`、`management/commands/`。代码存在不等于测试环境或生产已经启用。

## 2. Gate

每个 WP 必须通过：代码审查 → 单元/集成测试 → `manage.py check` → 测试环境 dry-run → 数据/索引影响评估 → 备份和授权 → 生产小范围执行 → 服务/查询/一致性验收。

## 3. 记录模板

实施记录必须写日期、状态（完成/部分完成/阻塞）、实际修改文件、精确命令及结果、数据库/ES/服务影响、commit、回滚点、未完成项和残余风险。不得用“设计完成”代替命令证据，不得记录凭据、正文或大段日志。
