# 生产备份与恢复手册

## 1. 备份清单

MySQL 数据与迁移状态；Mongo 正式正文、草稿/历史集合；MinIO 对象；Elasticsearch snapshot（内容索引、旧 Wagtail 索引、日志索引按范围记录）；项目 commit、systemd unit、Nginx/uWSGI 配置和环境文件安全副本。凭据与备份内容不得进入 Git。

## 2. 验证证据

每份备份记录时间、范围、目标路径、校验和、大小和恢复测试结果。ES snapshot 使用 `include_global_state=false`；恢复不得覆盖集群级设置。恢复前确认有足够磁盘、ES repository 可读、Mongo/MySQL 目标为空或已隔离。

## 3. 恢复顺序

停止受影响应用写入 → 恢复 MySQL → 恢复 Mongo 和对象存储 → 恢复 ES 索引/alias → 执行 Django check 和搜索一致性 → 启动 Django → Worker → Beat → Filebeat → 验证首页、后台、搜索、评论和日志。

## 4. 禁止操作

禁止 `flush`、删除 Mongo 正文、`docker compose down -v`、删除 snapshot 目录、通配符删除索引和未经授权的批量修复。恢复失败保留现场、日志和原备份，使用上一回滚点。
