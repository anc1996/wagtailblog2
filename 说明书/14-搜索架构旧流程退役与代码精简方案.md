## 1. 文档信息

- 当前基线：`806b639803db5b444a4366401fe65e9c641c6105`。

## 2. 结论摘要

当前正式运行路径只有三条：

1. `type=blog`：查询独立精简内容索引 alias，正文来自 MongoDB 正式正文的索引投影。
2. `type=pages`：查询 Wagtail 默认 Page 索引，QuerySet 只保留 `live().public()` 并排除 `BlogPage`。
3. `type=all`：复用同一个 Pages 查询函数，将 Blog 独立索引结果和普通 Pages 结果联邦合并并去重。

所以不能删除整个 Wagtail 默认 Page backend 或 Page 索引。普通页面搜索、`pages`、`all` 的 Pages 分支、Wagtail 后台搜索和 chooser 仍依赖它们。

本方案真正要退役的是：影子查询运行时、影子配置、只用于新旧差异诊断的临时命令，以及经静态证明没有正式调用方的旧 DSL/惰性结果对象。同步模型、Outbox、Delivery、Target/Build、tombstone、alias、回滚和一致性检查属于当前架构，必须保留。

## 3. 已核对的代码规律

| 组件 | 当前职责 | 决策 |
| --- | --- | --- |
| `apps/search/core.py::perform_search` | 解析请求并分派 blog/pages/all | 保留，作为统一入口 |
| `services/content_query.py` | 独立 Blog 内容索引查询、公开结果适配、游标 | 保留；只删除 shadow getter |
| `services/pages_query.py` | 普通公开 Pages QuerySet | 保留，不能删除 |
| `services/federated_query.py` | all 的 Blog + Pages 合并、去重、排序、游标 | 保留，属于正式路径 |
| `services/highlights.py` | 独立索引的安全高亮 | 保留 |
| `core.py::HighlightedSearchResults` | Pages 分支查询和安全高亮 | 保留，不能误当旧 shadow 代码 |
| `services/shadow.py` | 采样、异步影子请求、熔断和差异日志 | WP8C 退役 |
| `core.py::_wrap_with_content_search_shadow` | 给 Pages 结果包装 shadow 请求 | WP8C 退役 |
| `core.py::ESLazyResults` 等旧 DSL | 历史查询实现 | WP8D 先证明无调用再退役 |
| `search_compare_content_query` | 新旧查询只读差异报告 | 报告归档后 WP8D 退役 |
| `services/alias.py` 和同步命令 | 独立索引运维与回滚 | 保留 |

Wagtail 7.4.2 的自动更新由 `modelsearch` 信号层处理：`post_save` 会为 indexed model 投递更新，`post_delete` 会删除对象；`search_auto_update=False` 只影响自动更新登记，不等于从全量 `update_index` 对象集合排除。因此，历史清理后是否会回涨必须通过真实生命周期和重建验证，不能凭一次删除结果判断。

## 4. 目标与非目标

### 4.1 目标

- 测试环境只保留 Blog 独立搜索、普通 Pages 搜索和联邦 all 三条正式请求路径。
- 删除 shadow 后不再产生额外线程、ES 请求、采样日志或熔断状态。
- 删除无调用方的旧查询实现，降低维护和误用风险。
- 保留普通 Page 搜索、后台/chooser、内容同步、alias 回滚和一致性检查。
- 每个批次有可验证 Gate、数据影响说明和代码回滚点。

### 4.2 非目标

- 不删除默认 Wagtail Page backend 或普通 Page 索引。
- 不删除 `Page.search_fields`、核心 `AutocompleteField` 或 BlogPage 的正式搜索字段。
- 不删除 Mongo 正文、草稿、revision、MySQL 业务行或搜索状态。
- 不删除生产 ES 索引、alias、v002 回滚点、配置或 systemd 服务。
- 不执行生产 migration、回填、alias 切换、索引删除或服务重启。

## 5. 目标运行拓扑

```text
搜索请求
  +-- blog  -> ContentSearch read alias -> 独立 Blog 精简索引
  +-- pages -> build_public_pages_queryset -> Wagtail default Page backend
  +-- all   -> blog 查询 + pages 查询 -> 主键去重 -> 联邦排序/分页/游标
```

写入链路不变：

```text
BlogPage 发布/取消发布/删除/限制变化
  -> MySQL State + Outbox
  -> maintenance Worker 租约、重试
  -> Target Delivery
  -> 独立内容索引
```

## 6. 分批实施计划

### WP8A：冻结基线和引用清单

推荐模型：`gpt-5.6-terra`；推理强度：高。

#### 实施内容

1. 记录测试代码 SHA、服务、`.env.test` 正式开关、内容 alias、索引文档数和普通 Page 索引状态。
2. 静态列出 shadow、compare、secondary、legacy DSL 的所有定义和引用。
3. 用 AST/导入检查区分正式调用、测试调用和仅定义未调用，不能只按文件名删除。
4. 建立删除前清单：代码、测试 ES index/template/alias、测试 MySQL 搜索状态和测试 Mongo 只读计数。
5. 确认测试命令不会读取或写入生产连接和生产命名空间。

#### Gate 与回滚

- `blog/pages/all` API 和 HTML 基线可复现。
- `search_sync_status` 无未解释 pending/retry/dead/processing。
- 工作树干净，测试前缀和生产前缀明确分离。
- 本批只新增报告或 fixture，回退 commit 即可，无数据回滚。

### WP8B：证明 BlogPage 不回写默认 Page 索引

推荐模型：`gpt-5.6-terra`；推理强度：高。这是后续清理的阻断 Gate。

#### 实施内容

1. 在测试 ES 创建带测试前缀的默认 Page 索引副本。
2. 对测试 BlogPage 执行保存草稿、发布、重新发布、取消发布、访问限制变化和删除。
3. 每个动作后检查独立内容索引和默认 Page 索引：公开 Blog 只应在独立索引，普通 Page 仍应在默认索引。
4. 执行一次 Wagtail `update_index` 或项目等价重建，确认 BlogPage 不会再次写回默认索引。
5. 验证未发布、受限和删除页面在两个公开查询入口均不可见。
6. 如果 `search_auto_update=False` 不能阻止全量重建，不能删除 BlogPage 清理维护命令；应保留受控精确清理，或实现并测试受支持的索引过滤扩展点。

#### Gate

- 发布、取消发布、删除、限制变化和重建全部通过。
- 普通 Page、后台搜索和 chooser 无回归。
- 草稿、受限页面和 Mongo 草稿正文不出现在公开结果。
- BlogPage 默认索引处理策略有代码和测试证据。

#### 回滚

回退代码 commit；测试索引删除只允许匹配测试前缀，并先核对不含生产名称。不得恢复或删除 Mongo 正文。

### WP8C：退役 shadow runtime

推荐模型：`gpt-5.6-terra`；推理强度：高。

#### 预计修改

- 清理运维文档中的当前 shadow 启动说明；历史实施记录必须保留并标明历史状态。

#### 不删除
