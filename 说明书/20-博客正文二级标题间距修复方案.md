# 博客正文二级标题间距修复方案

## 背景与现状证据

- 用户反馈测试站博客文章的二级标题与紧随正文之间的空白过大。
- `wagtailblog3/static/css/site-theme.css` 中的二级标题规则仅设置了 `margin-top: 2.4em`，未覆盖 GitHub Markdown 样式提供的 `16px` 下外边距。
- 页面模板将 Markdown/Rich Text 块使用 `.markdown-body` 渲染，后加载的 GitHub Markdown 样式会为标题和段落各自设置默认外边距。

## 目标和非目标

目标：收紧博客正文中二级标题与紧随正文的垂直间距，使章节标题、分隔线和导读正文成为更连贯的阅读单元。

非目标：不修改 Markdown 正文、StreamField 存储、模板结构、标题层级、其他标题级别、服务配置或生产环境。

## 设计与实施步骤

1. 在博客正文专用的 `h2` 规则中显式设置较小的下外边距，保留原有的章节上间距、字号、分隔线与锚点滚动偏移。
2. 更新页面引用的 `site-theme.css` 版本参数，避免浏览器缓存旧样式。
3. 在测试站按桌面与移动视口检查间距、内容溢出、控制台和锚点链接焦点路径。

## 修改与不修改的文件

- 修改：`wagtailblog3/static/css/site-theme.css`、`wagtailblog3/templates/base.html`。
- 新增：本文档。
- 不修改：博客正文数据、模型、迁移、模板内容结构、JavaScript、服务和环境文件。

## 数据与服务影响

- 不读写数据库、MongoDB 正文、草稿或 revision 数据。
- 不需要迁移、服务重启或 `systemctl.md` 更新。
- 静态样式在测试服务重新请求页面后生效；生产发布须由用户另行确认。

## 测试与验收

- 静态检查：确认覆盖规则仅作用于 `.blog-page-wrapper .article-body-content h2`，并通过 `git diff --check`。
- 运行检查：在 WSL2 `wagtailblog-test` 环境运行 Django system check。
- 浏览器验收：测试站桌面及移动视口确认标题后的正文间距收紧、无横向溢出、无控制台错误，标题锚点按钮仍可键盘聚焦。

## 回滚点

- 回滚本次 `site-theme.css` 的下外边距声明与 `base.html` 的静态版本参数即可恢复原有版式；不涉及数据回滚。

## 需要确认的生产操作与残余风险

- 本次仅修改工作区与测试站，不提交、推送或部署生产。
- 残余风险：浏览器自动化若仍受 WSL2 Chromium 沙箱限制，将以静态规则检查和可用替代浏览器入口补充验收，并明确记录未完成项。

## 模型/推理强度建议

- 事实收集：`gpt-5.6-luna`，低至中推理；任务为局部 CSS 定位与既有规则核对。
- 实现：`gpt-5.6-terra`，中推理；需要在多层 CSS 级联中做最小、可验证的覆盖。
- 升级条件：涉及生产发布、页面结构调整、跨浏览器兼容异常或数据/服务影响时，升级为 `gpt-5.6-sol` 高推理并重新评估风险。
- 验证门禁：样式作用域检查、WSL2 Django check、桌面和移动浏览器验收；未通过不得发布。
- 实际使用：当前会话使用可用 Codex 模型完成定位与局部实现，未触发升级条件。
