# 前端统一美化与企业级设计体系方案

## 1. 背景与现状证据

项目是以内容阅读、知识检索和 Wagtail 后台维护为核心的中文网站，不适合采用营销落地页式的重视觉重卡片方案。公开前端入口为 `templates/base.html`、`templates/includes/header.html` 和 `templates/includes/footer.html`；后台由 Wagtail 及多个项目定制视图组成。

当前已经具备可复用基础：`static/css/site-theme.css` 提供了亮/暗主题、颜色、圆角、阴影、内容宽度和过渡 token，`content-images.css` 等较新的模块已经消费 `--site-*` token。问题在于系统仍处于渐进叠加状态：`base.html` 先加载 Bootstrap/Gretzia，再加载页面域样式，最后叠加共享主题；博客、搜索、归档、评论和后台页面又各自维护颜色、尺寸和状态规则。

已核实的具体问题包括：

- `templates/blog/blog_index_page.html` 重复加载 `blog-index.css`，`templates/blog/author_detail.html` 重复加载 `blog-index.css` 与 `author-detail.css`，并且版本参数不一致。
- `static/css/site-theme.css` 已有共享 token，但 `comments.css`、搜索、归档和部分后台样式仍存在多套硬编码颜色；评论仍保留 Bootstrap 蓝色，与站点暖色主题和暗色模式不一致。
- `static/gretzia/css/style.css` 通过远程 Google Fonts `@import` 引入字体；静态目录约 54.8 MB，包含编辑器、图表、Mermaid、KaTeX 等按需资源，不能以“美化”为由直接清理。
- 后台搜索分析将排序表头实现为仅鼠标可点击的 `th`；趋势图只有 canvas 标注，无等价数据；归档和分析表格在小屏缺少统一可理解的响应式策略；部分后台模板没有继承 `wagtailadmin/base.html`。
- 后台登录壳已验证具备 skip link、可见焦点且 375px 无横向溢出；登录后定制报表尚未取得授权会话，必须在实施批次补做浏览器验收。

## 2. 企业级差距评估

| 维度 | 当前状态 | 企业级目标 | 差距 |
| --- | --- | --- | --- |
| 设计 token | 前台有 `--site-*`，各页面和后台仍有硬编码 | 全站按语义 token 消费颜色、间距、边框、状态和 motion | 中高 |
| 组件契约 | 页面各自定义卡片、表格、按钮和状态 | 公共按钮、卡片、表格、空态、错误态、图标按钮有统一变体与状态 | 高 |
| 级联治理 | Bootstrap/Gretzia/页面 CSS/共享主题多层覆盖 | 明确基础层、token 层、组件层、页面层及加载顺序 | 高 |
| 可访问性 | 部分 `focus-visible` 与主题切换已具备 | WCAG 2.2 AA 基线：键盘、可见焦点、状态语义、对比度、触控目标和图表等价信息 | 高 |
| 响应式 | 多数页面已有媒体查询 | 375/768/1024/1440 一致布局；小屏无非必要横滚；数据表有说明或卡片化方案 | 中高 |
| 性能 | 按内容块条件加载已有基础 | 清除重复 CSS、减少阻塞字体、按需加载并用尺寸预留控制 CLS | 中 |
| 测试与治理 | 局部 Playwright 证据存在 | 每批前后截图、控制台/网络、键盘路径、视觉回归和 token 禁止规则 | 高 |

对标基线采用内容优先的 Minimalism/Swiss 风格：清晰网格、高可读性、克制装饰、稳定信息层级和搜索入口优先。设计检索建议的冷灰蓝只作为对比参考，不替换站点既有暖棕主色；首期保留现有品牌色，先解决一致性和可用性。可访问性以 WCAG 2.2 AA 为最低验收线，重点包括焦点不被遮挡、键盘路径和最小目标尺寸。[W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/)

## 3. 目标与非目标

目标：建立共享视觉语言和改造顺序；将高频界面收敛到可审计 token 与组件契约；提升公开阅读页和后台业务页的响应式、可访问性和加载质量；每批保留可回滚的独立 commit。

非目标：不引入新的 CSS/JS 框架；不替换 Wagtail 后台整体视觉；不重写博客正文、Markdown、StreamField、搜索、评论数据或后台业务流程；不以一次大重构删除 Bootstrap、Gretzia、vendor 或媒体资产；不在本方案阶段发布生产。

## 4. 统一设计方向

1. 保留 `site-theme.css` 的暖色阅读主题、亮/暗模式和内容宽度，补齐语义 token，不重做品牌色。
2. 前台以正文阅读、目录、搜索和分类浏览为核心，控制卡片圆角不超过 8px；后台以表格、筛选、状态与效率为核心，不采用营销式 hero 或装饰卡片。
3. 图标沿用已存在的 Wagtail 图标或单一图标体系；图标按钮必须有可访问名称，状态不能只由颜色表达。
4. 建立 4px/8px 间距尺度、稳定的标题/正文/辅助文字层级、统一的焦点环和 150-250ms 交互时长；尊重 `prefers-reduced-motion`。

### JavaScript 与 jQuery 策略

`templates/base.html` 在底部全局加载 `static/gretzia/js/jquery.js`（jQuery 3.6.0），随后加载 Popper、Bootstrap 和页面插件。当前代码同时存在 jQuery 与原生 DOM/Event API：评论、表单、图片块、归档和旧版插件明显依赖 jQuery；搜索、博客索引、Mermaid、视频、可视化和拖拽等较新的脚本已使用 `fetch`、原生事件、Promise、PointerEvent 或模块化资源。

本项目不采用“把所有 JavaScript 统一改成 jQuery”的迁移目标：

- 短期保留全局 jQuery，保证 Bootstrap、Isotope、Owl、Lightbox、评论和校验插件的兼容性；不得在未盘点插件入口前移除或异步化它。
- 新增功能和需要 PointerEvent、passive listener、原生模块、`fetch` 或精细生命周期控制的脚本继续使用现代原生 JavaScript。
- 只有在单个模块内已有 jQuery 代码、且改写能减少重复选择器或修复事件委托问题时，才由 `luna` 做局部 jQuery 整理；不得跨模块机械替换。
- 由 `terra/sol` 负责的后续性能批次，先用实际请求体积、首屏脚本依赖和浏览器回归证明，再决定是否替换旧插件或拆分 jQuery 加载。该步骤不包含本批次。

## 5. 分批实施与员工分工

### 批次 A：低风险统一基线

由 `luna` 中推理承担，保持选择器和布局不变。

- 删除模板中重复 CSS 引用并统一版本参数。
- 将搜索、归档、侧栏等稳定的颜色/边框/圆角/阴影映射到现有 `--site-*` token。
- 为公开图标按钮、关闭按钮和移动导航补齐统一 `focus-visible`、可访问名称和至少 44px 触控命中区。
- 为图片补齐现有模式中的尺寸和延迟加载属性；修正文档与模板中明确的 alt 文本缺口。
- 为后台普通表格补 `caption`、`scope`、空态和横向滚动提示；只处理静态结构，不改变查询或业务行为。

验收：模板渲染与 `git diff --check`；Playwright 检查首页、博客索引、文章页、搜索页的 375/1440 视口、控制台、静态资源、横向溢出和键盘焦点。

### 批次 B：跨页面设计系统与后台语义

由 `terra` 中到高推理承担。

- 定义前台 token 使用边界，新增后台语义 token 映射，逐步移除组件内 raw hex，不删除旧基础层。
- 统一 Wagtail 自定义页的 base/header/block 契约；将排序表头改为可键盘操作的按钮并维护 `aria-sort` 和结果状态。
- 为 canvas 图表提供文本摘要、可访问数据表或等价展开内容；为加载、错误和空态建立状态语义。
- 处理评论模块、正文内容块、暗色模式和 sticky/拖拽交互的主题一致性，先建立回归案例再修改。

验收：登录后后台 Playwright 桌面/375/768/1440、键盘全路径、排序与删除确认、图表等价内容、移动表格、控制台与网络；Django 检查及相关测试。

### 批次 C：性能与旧层收敛

由 `terra` 高推理，必要时由 `sol` 复核。

- 建立 CSS/JS 引用图和首屏请求基线，评估字体加载、未使用的全局 Font Awesome 和旧样式层。
- 仅在引用和生产静态清单证据完备后，按页面替换或延迟加载；不删除任何 vendor/编辑器资源。
- 建立视觉回归基线与 token lint/约束，防止后续再次加入绕过 token 的样式。

验收：LCP/CLS/INP 采样、网络瀑布、暗色模式、浏览器矩阵和生产前后资源差异；任何资源删除、服务变更或生产缓存策略需另行确认。

## 6. 模型/推理强度建议

| 角色与工作 | 模型/强度 | 升级条件 | 验证门禁 |
| --- | --- | --- | --- |
| 文件盘点、重复引用、token 替换、静态语义补全 | `gpt-5.6-luna` 中 | 影响全局级联、行为脚本或暗色模式时升 `terra` | diff、模板检查、桌面/移动截图 |
| 单页响应式修复、图片属性、普通表格包装 | `gpt-5.6-luna` 中 | 涉及动态渲染、图表、登录后台或交互状态时升 `terra` | Playwright、键盘、控制台/网络 |
| token 架构、样式层顺序、文章/评论整合、后台交互 | `gpt-5.6-terra` 中/高 | 跨服务、复杂动画、生产发布或不可逆资源清理时升 `sol` | 回归矩阵、相关 Django 测试、人工视觉审查 |
| 生产发布、资源清理、缓存/CDN 或服务变更 | `gpt-5.6-sol` 高 | 回滚或证据冲突 | 备份、精确 commit、健康检查、回滚演练 |

实际使用：本轮由两名 `luna` 完成样式资产与公开页采样任务：公开首页与搜索页在 1280px 视口未出现横向溢出、控制台无错误或警告；博客索引在 390px 视口完成采样，但文章页与归档页因本地测试服务退出未完成验收。该采样未登录、未调用写接口。另有一名 `terra` 完成后台结构、可访问性和登录壳浏览器审计。主 agent 使用当前会话可用模型完成整合，未向外部模型发送源码、凭据或正文。

## 7. 文件范围、数据与服务影响

首批预计修改：`templates/base.html`、公开页相关模板、`static/css/site-theme.css`、搜索/归档/侧栏的局部 CSS，以及明确存在重复引用的模板。后台批次再单独触及 `templates/wagtailadmin/`、`templates/search/admin/`、`templates/archive/admin/` 和对应静态文件。

本方案不修改模型、迁移、页面内容、MongoDB、搜索索引、Redis、MinIO、Celery、systemd 或环境文件。仅样式和模板代码发布时需要按代码发布流程同步静态资源并重启受影响 Web 服务；生产执行前另行确认。

## 8. 回滚与待确认事项

每个批次独立提交；回滚为恢复到该批次前的 commit 并重新收集静态资源。不得混入与前端无关的未跟踪文件。

需要用户确认后实施：首批范围是否按“批次 A”覆盖公开首页、博客索引、文章页、搜索页和后台普通表格；后台登录后页面的验收账号或可用授权会话；是否将站点当前暖棕主题作为长期品牌基线。

## 10. 多角色联合设计架构（2026-08-25）

### 10.1 角色提示词的工程化取舍

视觉艺术家、UI/UX 设计师和前端开发专家三个观察角度适合本项目，但人格类型和情感激励不作为设计决策证据。实际协作按可交付职责划分：视觉角色定义品牌气质、版式和内容类型表达；UI/UX 角色定义信息架构、用户任务流、可访问性和状态反馈；前端角色定义 CSS/JS 分层、依赖边界、性能、测试和回滚。三者共同遵守现有 Wagtail 内容模型、URL、主题 token 和生产门禁。

### 10.2 产品定位与视觉母题

站点定位为“中文知识库式编辑出版系统”，服务技术、数据库、网络、系统、AI、理论学习、公文和行测等内容。视觉母题采用理性编辑型的 Minimalism/Swiss 网格：高可读性、稳定层级、克制装饰、搜索优先和轻量动效。保留现有暖棕品牌色和亮/暗主题，不采用营销 Hero、玻璃拟态、发光渐变、装饰性 Bento 或每个栏目一套皮肤。

统一品牌角色：

- 暖棕负责品牌、主操作、链接和阅读进度；深棕负责悬停与当前状态。
- 青绿色负责焦点、信息提示和技术类辅助标识；成功与危险色只表达真实状态。
- 米白、浅灰、暖黑负责阅读表面；正文宽度继续以现有 `--site-reading-width: 780px` 为基线。
- 中文正文优先系统无衬线字体并保持 16-18px、1.75-1.9 行高；Playfair Display 仅保留为少量英文编辑性点缀，不用它承担中文层级。
- 内容域差异通过眉标、图标、标签、元数据和内容块表达，不通过整页换色表达。技术/AI 强调代码、架构图、版本和实验结论；理论学习强调章节、引用和知识关系；公文强调来源、日期、文号和规整目录；行测强调题型、难度、答案与解析状态。

### 10.4 页面与用户任务流

全局一级导航收敛为“首页、专栏、探索、作者”；探索承载全文搜索、标签目录、时间归档和 RSS。是否改变 Wagtail 动态树菜单须在实施前核对内容团队配置，因此首批只统一视觉和交互契约，不直接改变现有 URL 或菜单数据。

- 首页：从轮播和杂项侧栏转向一个精选入口、最新/热门内容和专题专栏；归档、标签、随机作者下沉为“探索更多”。自动轮播必须支持暂停并遵守 `prefers-reduced-motion`，否则使用静态精选布局。
- 索引与搜索：文章卡共享类型、日期、作者、标签、摘要和阅读数据；搜索负责主动检索，专栏/标签负责主题浏览，归档负责时间浏览，作者负责人物浏览。筛选 URL 可分享，浏览器返回后保持状态。
- 文章：宽屏保留目录、正文和辅助栏，但目录与辅助栏降低对比度并可折叠；移动端顺序为标题、目录入口、正文、反应、相关推荐和前后篇。正文是唯一视觉主角，拖拽手柄与布局状态保持低干扰。
- 评论：默认突出阅读和输入，高级 Markdown、公式和表情工具渐进展开；回复、编辑、删除、加载和错误状态必须有焦点管理与屏幕阅读器提示。
- 后台：报告入口按内容表现、搜索意图、社区健康、系统可观测分组；趋势 canvas 提供同数据摘要或表格，筛选、排序和状态可键盘操作。
