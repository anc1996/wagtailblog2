# 测试目录整理与冗余测试清理方案

## 1. 背景与现状证据

- `wagtailblog3/apps/blog` 当前约有 30 个 `test_*.py` 直接放在应用根目录，已有空的 `tests.py` 占位文件。
- `wagtailblog3/apps/search` 仍有一个根目录测试文件 `test_search_async.py`，其余测试已在 `tests/` 包内。
- `wagtailblog3/apps/archive` 仍有一个根目录测试文件 `test_archive_async.py`，并有空的 `tests.py` 占位文件。
- `wagtailblog3/tests/`、`apps/observability/tests/` 等目录已经采用包化结构，不应重复移动。
- `apps/base/tests.py`、`apps/portfolio/tests.py` 为空占位文件；`apps/comments/tests.py`、`apps/content_ai/tests.py` 含真实测试，不能删除。
- `apps/base/management/commands/test_email.py` 是管理命令，不是 Django 测试文件，不纳入移动或删除。

## 2. 目标与非目标

### 目标

1. 将应用测试统一放入各应用的 `tests/` 包。
2. 保留测试发现能力和现有测试覆盖，修正受影响的导入路径。
3. 删除已确认为空且无运行时用途的占位测试模块。
4. 为后续代码扫描提供明确的测试目录边界。

### 非目标

- 不删除仅因名称旧、编号旧或最近修改时间较早的真实测试。
- 不修改 Django/Wagtail 运行时代码、数据库、MongoDB、Elasticsearch 或服务配置。
- 不把管理命令、测试夹具和全局测试重复移动。
- 不修改历史说明书中的既有测试命令记录；仅更新仍作为当前运行入口的文档。

## 3. 实施范围

### 移动

- `apps/blog/test_*.py` → `apps/blog/tests/test_*.py`
- `apps/search/test_search_async.py` → `apps/search/tests/test_search_async.py`
- `apps/archive/test_archive_async.py` → `apps/archive/tests/test_archive_async.py`

为 `blog`、`archive` 创建缺失的 `tests/__init__.py`；`search/tests/__init__.py` 已存在。

### 删除

仅删除已核实为空、无引用、无测试用例的占位模块：

- `apps/blog/tests.py`
- `apps/archive/tests.py`
- `apps/base/tests.py`
- `apps/portfolio/tests.py`

### 保留

- `wagtailblog3/tests/**` 全局测试
- `apps/observability/tests/**`
- `apps/comments/tests.py`、`apps/content_ai/tests.py`
- `apps/base/management/commands/test_email.py`

## 4. 导入与发现兼容

- 移动后修正 `from .models` 等相对导入为适配 `tests` 包层级的 `from ..models`。
- 当前定向测试命令中的 `blog.test_xxx` 路径改为 `blog.tests.test_xxx`；完整入口继续使用 `python manage.py test blog`。
- 通过测试发现数量、定向测试和 `compileall` 验证没有遗漏。

## 5. 验证与验收

- `WAGTAILBLOG_ENV=test python manage.py check`
- `python manage.py test blog search archive --keepdb`
- 关键模块定向测试（发布、删除、Mongo 正文、搜索同步）
- `python -m compileall -q wagtailblog3`
- `git diff --check`
- `rg --files` 核对根目录不再有应移动的应用测试文件

## 6. 数据、服务与生产影响

本批只改变 Python 测试文件路径和占位文件，不执行迁移、不访问生产数据、不修改索引、不重启服务。生产同步属于测试/文档代码同步，默认无需重启运行服务。

## 7. 回滚点

使用同一提交回滚即可恢复原文件路径和占位模块；不涉及数据库回滚。移动操作使用 `git mv`，保留历史追踪。

## 8. 模型/推理强度建议

- 事实盘点：`gpt-5.6-luna` 低/中推理，检查文件清单、引用和测试发现。
- 文件整理与测试修正：`gpt-5.6-terra` 中推理，范围局部且无运行时行为变更。
- 若发现测试语义重复、删除会影响发布门禁或出现发现数量冲突，升级 `gpt-5.6-sol` 高推理并暂停删除。
