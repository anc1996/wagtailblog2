# 搜索架构改造与演进历程摘要

> **归档收敛说明**：本篇由历史原始文档 `09-搜索架构容量与演进方案.md`、`10-搜索架构实施计划.md`、`11-搜索架构生产部署方案.md`、`13-全站联邦搜索改造方案.md`、`14-搜索架构旧流程退役与代码精简方案.md`、`28-Wagtail后台页面搜索链路分析.md`、`30-搜索热词与搜索分析方案.md`、`31-ContentSearchScopeJob权限闭环方案.md`、`32-BrowserSkill模拟用户权限闭环端到端验证方案.md` 及 `搜索流程.md` 提炼收敛而成。剔除反复修改的过渡计划与阶段性排查日志，完整记录搜索系统从内置耦合到独立企业级检索体系的演进路径。

## 1. 改造背景与痛点动因 (原 09, 28)

- **原生搜索局限**：Wagtail 原生基于数据库或基础 ES 后端绑定的搜索机制存在严重弊端：与 OLTP 事务强耦合、中文分词精度低、大文本扫描拖慢数据库、难以支持热词聚合与高级布尔过滤。
- **后台与前台链路混乱**：后台管理页面搜索、前台站内检索、多模型聚合检索分散在不同模块，缺乏统一的索引模型与版本管理。
- **核心改造决策**：彻底放弃 Wagtail 内置搜索作为对外检索入口，**自建独立的 Elasticsearch 内容检索架构**，建立只读别名（Read Alias）、事务性发件箱（Outbox）及专用管理后台。

---

## 2. 独立内容搜索架构核心设计 (原 09, 11, 搜索流程)

### 2.1 索引物理结构与平滑切换
- **版本化物理索引**：定义 `wagtailblog-prod-content-v*`（如当前基线 `v005`），配置 `ik_max_word` 细粒度索引分词与 `ik_smart` 精准查询分词，并引入拼音与高亮增强。
- **只读别名机制**：应用层仅面向别名 `wagtailblog-prod-content-read` 查询。
- **零停机全量重建（Reindex）**：
  1. 创建新版本物理索引（如 `v006`）。
  2. 批量同步 MySQL 与 MongoDB 数据进入新索引。
  3. 通过 ES 原子操作将别名指针切换至新索引。
  4. 验证无误后注销并清理旧版本物理索引。

### 2.2 事务性发件箱（Outbox）与异步投递
为避免数据库与搜索引擎“双写不一致”，系统全面采用 Outbox 模式：
1. **本地事务记录**：文章在 MySQL/Mongo 保存或发布时，在同一事务内向 `search_searchdelivery` 表写入一条待投递事件。
2. **异步队列消费**：Celery 维护 Worker（`wagtailblog3-celery-maintenance`，消费 `-Q maintenance`）监听并批量抓取投递事件，调用 ES Bulk API 写入。
3. **退避补偿与死信防护**：投递失败采用指数退避重试，超出最大重试次数转入 Dead 状态并报警，主请求响应毫秒级不受影响。

## 3. 树形权限闭环与作用域任务 (原 31, 32)

- **树形隐私继承难题**：Wagtail 页面树支持对父页面设置访问权限（如密码保护、私密、特定用户组可见）。若直接把所有已发布文章推入 ES，会导致匿名读者在检索时泄露私密文章标题或摘要。
- **ContentSearchScopeJob 架构方案**：
  - 设计异步作用域计算任务 `ContentSearchScopeJob`。
  - 当父页面权限发生变动或页面发生树状移动（Move）时，触发该任务深度遍历子树节点，递归刷新子页面的 `view_restrictions` 标记，同步更新 ES 索引中的权限过滤字段。
  - 前台查询时在 Elasticsearch QueryDSL 中强行注入权限过滤子句，彻底实现未授权内容的端到端阻断。

---

## 4. 搜索热词聚合与运营分析看板 (原 30)

- **时序日志收集**：用户的检索请求（关键词、检索时间、命中数量、耗时、客户端指纹）通过轻量管道异步记入搜索分析数据表。
- **可视化控制台**：
  - 后台提供搜索分析看板，包含核心 KPI 汇总卡片、热门词环形占比图、搜索趋势时序曲线图。
  - 支持热词管理（置顶推荐、同义词引导、违禁词屏蔽），驱动站内内容推荐。

---

## 5. 旧流程退役与代码精简收官 (原 14)

搜索改造进入成熟期后，对旧有代码实施了彻底的“降熵清理”：
1. **下线旧同步钩子**：移除了原有的 Wagtail `after_publish_page` 强行同步旧索引的同步阻塞钩子。
2. **清理冗余视图**：废弃了早期基于数据库 LIKE 查询的兜底搜索接口，统一收敛至基于 ES 别名的现代化检索 API。
3. **消除冗余依赖**：精简了无用的分词辅助包，生产环境仅保留维护良好、受监控守护的单一搜索流。
