# 博客正文存储演进与 Mongo 孤儿治理历程摘要

> **归档收敛说明**：本篇由历史原始文档 `29-BlogPage正文存储与生命周期分析.md`、`33-Mongo孤儿正文可视化审计与安全清理实施方案.md` 及 `34-Mongo孤儿正文抽屉清理按钮与批量勾选测试方案.md` 提炼收敛而成。剔除反复比对的中间测试快照与流水日志，保留正文异构存储核心架构、生命周期状态机及孤儿正文治理的核心逻辑。

## 1. 异构存储分层架构与决策动因 (原 29)

- **核心矛盾**：Wagtail 原生设计将 StreamField 完整富文本与每次编辑保存生成的历史 Revision 均塞入 MySQL 关系数据库。随着文章数量、字数、插入图片及自动保存草稿的递增，MySQL 单表急剧膨胀，备份锁表时间过长，查询性能显著恶化。
- **异构分层决策**：
  - **MySQL（元数据与关系中心）**：仅存储页面树拓扑、权限控制、URL 别名、发布状态以及一个轻量级的关联指针 `mongo_content_id`。MySQL 中的 `BlogPage.body` 保持为空或极简存根。
  - **MongoDB 7.0（正文大文本中心）**：专门承载长文本 StreamField 实际内容，利用文档型数据库天然的高压缩比与灵活 Schema 特性。

### 1.1 MongoDB 三大集合规划
1. `blog_page_contents`：已正式发布的文章正文内容，以 `mongo_content_id` 为主键索引。
2. `blog_page_revisions`：历史版本快照集合，按 Wagtail Revision ID 强绑定，支持任意历史版本的无损回滚。
3. `blog_page_drafts`：编辑中未发布的实时草稿暂存集合。

## 2. 页面生命周期与水合（Hydration）保护机制 (原 29)

系统建立了严密的正文加载与保存防御机制，杜绝任何阶段的正文丢失：
- **编辑态反向水合**：当管理员在 Wagtail 后台打开文章编辑页时，`BlogPageForm` 拦截初始化流程，根据当前页面绑定的 `mongo_content_id` 或历史版本指针从 MongoDB 提取长文本，反向水合（Hydrate）注入前端 StreamField 结构中。
- **正文防冲刷红线（关键安全边界）**：
  若 MongoDB 暂时失联、连接超时或发生故障，表单水合将失败并报错。**此时系统强制阻断保存动作，绝对禁止将空表单保存入库**，从而保护历史正文不被空白数据覆写。
- **发布态原子流转**：
  用户点击“发布”时，首先向 MongoDB 写入新正文并取得生成的 ID，随后在 MySQL 事务中更新 `mongo_content_id` 并触发 Outbox 检索同步，确保多库一致性。

## 3. Mongo 孤儿正文成因与可视化审计治理 (原 33, 34)

### 3.1 孤儿正文成因
在长期运行中，以下场景会导致 MongoDB 中残留无主数据（孤儿正文）：
1. 页面在 Wagtail 后台被物理硬删除（Hard Delete），但当时的删除事务未级联清理对应的 MongoDB 正文。
2. 异常中断的 Markdown 批量导入操作，正文已写入 Mongo，但 MySQL 页面创建事务回滚。
3. 历史废弃草稿与无用 Revision 随时间推移积累。

### 3.2 可视化审计控制台与安全清理方案
为消除存储浪费并维护多库严格一致性，设计并落地了孤儿正文可视化审计工具：
1. **全量交叉扫描算法**：
   - 定时任务或管理员手动触发扫描。
   - 提取 MongoDB 所有正文 ID，与 MySQL `blog_blogpage` 正在引用的 ID、`wagtailcore_revision` 包含的 ID 进行差集计算，精准圈定孤儿集合。
2. **抽屉式审计与预览界面**：
   - 在 Wagtail 运维后台提供专门的“Mongo 孤儿正文审计”看板。
   - 列表展示孤儿数据的创建时间、预估字数、最后更新时间，并提供**“抽屉式（Drawer）内容预览”**，允许管理员在操作前人工肉眼核验正文片断，确保非误判数据。
3. **安全物理清理与备份留存**：
   - 支持单项清理与批量勾选清理。
   - 执行清理前，系统强制将待清理文档导出为本地临时 JSON 备份，再调用 MongoDB 物理删除 API，具备可追溯与可恢复能力。
