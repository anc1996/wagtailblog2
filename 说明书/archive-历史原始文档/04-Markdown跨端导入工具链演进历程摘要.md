# Markdown 跨端导入工具链演进历程摘要

> **归档收敛说明**：本篇由历史原始文档 `17-Markdown本地导入博客方案.md`、`18-Markdown本地导入实施计划与任务包.md`、`19-Markdown导入Windows客户端Exe方案.md` 及 `21-浏览器脚本直连Markdown导入博客方案.md` 提炼收敛而成。去除开发中关于打包排错、依赖冲突的琐碎日志，保留工具链从本地脚本演化至浏览器直连插件的技术架构决策。

---

## 1. 业务痛点与协议基线 (原 17, 18)

- **内容创作现状**：博主普遍习惯使用 Typora、Obsidian 或 VS Code 本地撰写 Markdown 文档，文章头部包含标准 YAML FrontMatter 元数据（标题、发布日期、分类、标签、封面等），并内嵌本地相对路径或远程防盗链图片。
- **痛点**：通过 Wagtail 原生后台逐篇复制、手动排版、重选分类并重新逐张上传图片极其低效且容易出错。
- **标准 FrontMatter 协议定义**：
  ```yaml
  ---
  title: "文章标题"
  date: 2026-08-01 10:00:00
  categories: ["架构设计", "后端开发"]
  tags: ["Django", "Wagtail", "ES"]
  cover: "./images/cover.jpg"
  summary: "文章摘要简述"
  ---
  # 正文开始...
  ```

## 2. 工具链演进三阶段 (原 17, 19, 21)

```
[阶段一: 本地 Python 命令行脚本]
       │
       ▼ (封装为桌面交互界面)
[阶段二: Windows PyInstaller 独立 Exe 客户端]
       │
       ▼ (突破打包与更新束缚，利用既有后台会话)
[阶段三: 浏览器油猴直连脚本 + 专用服务端导入 API] (当前最终形态)
```

### 2.1 阶段一：本地 Python CLI 工具（原 17, 18）
- 编写独立的 Python 扫描脚本，读取本地文件夹中的 `.md` 文件。
- 解析 FrontMatter，转换内嵌图片，直接通过 Django ORM 或基础 HTTP API 推送。
- *局限*：需要本地部署 Python 环境与特定依赖，对普通创作者使用门槛较高。

### 2.2 阶段二：Windows PyInstaller 桌面客户端（原 19）
- 采用 PyQt/Tkinter 开发可视化客户端，利用 PyInstaller 打包为单文件 `MarkdownImporter.exe`。
- 支持拖拽导入、批量校验与进度条显示。
- *局限*：服务端 API 契约更新时客户端需要重新打包分发；本地保存静态 Token 存在凭据泄露风险。

### 2.3 阶段三：浏览器脚本直连导入方案（当前最优解，原 21）
- **核心思路**：创作者在已登录 Wagtail 管理后台的浏览器中，借助 Tampermonkey 油猴脚本或书签脚本（Bookmarklet）实现“即开即用”。
- **三大优势**：
  1. **零安装负担**：无需安装本地环境或客户端软件，浏览器内原生运行。
  2. **会话无缝继承**：直接复用当前浏览器的登录态 Cookie / CSRF Token，天然保障操作权限。
  3. **客户端解析与防盗链代理**：在浏览器前端直接解析 Markdown 语法并拆解图片；对于带防盗链的外部图片，由后端专用导入视图代理抓取并安全转存至 MinIO。

## 3. 服务端安全架构与草稿保存闭环 (原 18, 21)

- **专用导入 API**：`/api/blog/markdown-import/`
  - 强制 CORS 白名单与 AES-256-GCM 动态 Token 验证。
  - 严格参数校验（检查分类与标签是否存在，不存在时自动按策略补充或回退默认分类）。
- **图片安全转存流水线**：
  - 提取正文中所有图片链接。
  - 远程图片服务端流式下载并校验 MIME 类型（防恶意脚本伪装）。
  - 统一调用 Wagtail Image 库完成压缩、缩略图派生并转存 MinIO，将正文图片占位符替换为合法的 Wagtail 图像标签。
- **草稿态保护闭环**：导入文章默认落地为**“未发布草稿”**（Draft），不直接触碰线上正式页面，必须由编辑人员在后台人工二次审阅后点击发布，杜绝批量误操作风险。
