# AI 元数据生成与知识库 RAG 方案历程摘要

> **归档收敛说明**：本篇由历史原始文档 `16-AI博客正文元数据生成方案.md` 及 `25-博客知识库语义搜索与工作报告生成方案.md` 提炼收敛而成。剔除早期尝试第三方集成失败的调试日志与来回推翻的提示词参数细节，系统性记录自建 `content_ai` 应用、三段提示词资产库及知识库语义增强方案的核心决策。

## 1. 架构选型反思与第三方插件退役 (原 16)

- **历史方案困境**：项目初期曾引入第三方插件 `wagtail-ai==3.1.1`，但在实际落地中暴露出严重缺陷：
  1. 深度绑定老旧 OpenAI Completions 接口，不支持 DeepSeek 等国内主流大模型。
  2. 提示词硬编码在源码中，无法针对公文、技术博客、新闻快讯等多体裁动态配置。
  3. 插件侵入 Wagtail 编辑面板底层逻辑，在升级 Wagtail 7.4/8.0 时频繁引发表单组件崩溃。
- **架构重构决策**：彻底卸载 `wagtail-ai`，恢复原生 `FieldPanel`，**新建完全解耦的独立子应用 `content_ai`**（`wagtailblog3/apps/content_ai`），自主掌控元数据生成与提示词资产。

## 2. 独立应用 `content_ai` 与三段提示词体系 (原 16)

### 2.1 数据模型设计：`BlogMetadataPromptTemplate`
- **模型字段**：
  - `name` / `description`：模板名称与用途说明。
  - `title_prompt`：标题生成指导词（控制字数在 50 字以内，凸显技术重点）。
  - `intro_prompt`：导语生成指导词（控制在 150 字以内，纯文本精炼概括）。
  - `tags_prompt`：标签提取指导词（约束提取 3-5 个规范领域标签）。
  - `is_active` / `version`：软停用标记与自增版本号，禁止物理删除以保证历史可审计。
- **预置模板资产库（ID 1~8）**：
  后台预先固化 8 套针对深度技术剖析、公文材料汇总、开发实战教程、业务周报总结等不同应用场景的标准提示词，管理员可随时在线调优。

### 2.2 编辑态内存提取与 Draftail 富文本同步
- **零触碰 MongoDB 原则**：前端脚本仅从当前浏览器编辑面板提取未保存的实时 StreamField 内存状态，不提前向 MongoDB 发起读取或写入，严守正文保护边界。
- **标准响应契约**：服务端接入 OpenAI / DeepSeek Responses API，强制 JSON Schema 约束输出：
  ```json
  {
    "title": "技术标题建议",
    "intro": "核心要点纯文本摘要",
    "tags": ["标签1", "标签2", "标签3"]
  }
  ```
- **Draftail React 状态同步**：针对 Wagtail 采用的 Draftail 富文本编辑器，通过 `DraftJS.EditorState` 原生更新组件内部状态，彻底根除了“传统给 hidden input 赋值导致界面空白丢失”的前端水合缺陷。

## 3. 博客知识库语义检索与工作报告生成演进 (原 25)

在实现单篇 AI 元数据生成后，方案进一步延伸至**全站知识库智能检索与报告生成（RAG）**：

### 3.1 混合检索（Hybrid RAG）架构
1. **内容切片与向量化**：对已发布的博客文章进行语义分块（Chunking），提取文本块元数据。
2. **混合检索路由**：
   - 传统关键词精准检索依托自建 Elasticsearch IK 分词索引（BM25）。
   - 概念泛化与语义联想依托密集向量相似度检索（Dense Retrieval）。
   - 最终通过倒数排名融合（RRF）算法计算全局相关度，大幅提升复杂技术问题的检索召回率。

### 3.2 周期性工作报告与摘要提炼
- **业务场景**：创作者或管理团队需按周/月汇总产出成果，自动生成工作总结。
- **生成工作流**：
  1. 用户在管理后台选定时间区间与分类范围。
  2. 系统自动检索该区间内已发布的全部技术文章与版本变更记录。
  3. 经过 LLM 上下文压缩与提炼，一键生成结构化的工作周报、技术突破清单与归档要点，打通“创作-发布-知识沉淀-报告输出”全流程。
