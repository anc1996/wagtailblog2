# Wagtail 8.0 与核心依赖升级历程摘要

> **归档收敛说明**：本篇由历史原始文档 `15-Wagtail扩展依赖升级方案.md` 及 `27-Wagtail 8.0升级可行性方案.md` 提炼收敛而成。剔除早期尝试性安装报错、pip dry-run 详细控制台回显及过渡验证记录，完整记录从 Wagtail 7.4.3 平稳跨越至 Wagtail 8.0 生产基线的核心考量与架构决策。

---

## 1. 升级动因与上游安全隐患消除 (原 15, 27)

- **安全防御迫切性**：Wagtail 7.4.3 及以下版本在上游陆续暴露出若干中高危安全漏洞：
  1. *页面管理 API 越权*：非授权编辑者可能意外绕过树状权限读取未公开草稿。
  2. *文档 SHA-1 哈希盲测*：通过上传接口的文件排重机制可能被攻击者探测私密文档指纹。
  3. *私有 Collection 数据泄露*：对特定顶级私密集合的授权可能异常穿透至未授权子集合。
- **现代化运行环境适配**：项目底座全面升级至 **Python 3.13.2 + Django 5.2.8 LTS**，旧版 Wagtail 在部分动态导入和多线程并发场景下存在废弃警告，亟需官方稳定支持。

## 3. 关键架构决策与技术细节收敛 (原 27)

### 3.1 数据库迁移：`wagtailcore.0098_apitoken`
- Wagtail 8.0 新增了系统级的 API Token 模型与鉴权表，通过 `0098_apitoken` 迁移引入。
- 项目在测试环境与生产环境均完成了该迁移的平稳应用，未产生任何数据断层。

### 3.2 关于 REST API v3 的战略决策：依赖就绪，路由暂封
- **背景**：Wagtail 8.0 正式提供了基于 Django Ninja 的 REST API v3 预览版。
- **架构决策**：**环境安装 `django-ninja` 依赖满足运行时要求，但在 `urls.py` 中显式不挂载 v3 路由**。
- **原因**：本项目已具备专门审计过的 Markdown 导入 API 与独立全文检索 API。在未建立严密的多租户权限建模与安全白名单前，盲目开放 v3 将扩大攻击面。

### 3.3 废弃特性下线与兼容调整
1. **表单字段保护**：`AbstractFormField.field_type` 新增 `required_on_save=True` 约束，更新相关表单模型确保草稿保存时类型字段非空。
2. **权限策略显式注册**：自定义 `SnippetViewSet` 与 `ModelViewSet` 由隐式自动注册转为显式权限策略声明，彻底消除了控制台废弃警告。
3. **老旧资产彻底剥离**：移除了早期 Wagtail 6.x/7.x 遗留的已废弃 `telepath` 打包脚本与旧版按钮扩展。
