# 工程规范与测试运维治理演进摘要

> **归档收敛说明**：本篇由历史原始文档 `12-生产备份与恢复手册.md`、`22-运行时代码注释与类型标注方案.md`、`24-多agent协作与模型技能调度方案.md` 及 `30-测试目录整理与冗余测试清理方案.md` 提炼收敛而成。去除多轮讨论的中间草稿与重复执行命令，系统性保留工程代码规范、测试目录标准化、多智能体协同流水线及多库容灾演练的核心规约。

## 1. 代码质量与类型契约治理 (原 22)

- **动因**：随着项目规模扩大与多 Agent 协同介入，代码一度出现无中文注释、显式类型丢失、关键业务意图模糊等“熵增”现象。
- **员工统一契约建立**：
  1. **中文业务导向注释**：新增与修改的代码必须补充中文注释，核心解释“为什么这样做”（业务约束、并发边界、数据保护、异常补偿），严禁逐行复述显而易见的代码。
  2. **静态类型提示（Type Hints）**：核心公共方法、API 序列化接口与服务层函数必须具备参数与返回值类型声明，严禁滥用 `Any` 掩盖未知契约。
  3. **模块头部与 Docstring 范本**：以 `apps/blog/admin_image_upload.py` 为全库工程标杆，确立完备的模块中文说明与函数 docstring 规范。

## 2. 测试工程目录治理与结构标准化 (原 30)

- **历史混乱局面**：
  - 早期约 30 个 `test_*.py` 散落在 `apps/blog/` 根目录。
  - 各个应用下存在多处空的 `tests.py` 占位文件，容易造成测试收集混淆。
- **标准化改造实施**：
  1. **统一包化结构**：将散落的测试用例统一归入各应用的 `tests/` 包（如 `blog/tests/`、`search/tests/`、`archive/tests/`）。
  2. **安全剔除占位空文件**：删除了 `apps/blog/tests.py`、`apps/base/tests.py` 等 4 个无用空文件。
  3. **保留全局与特例**：保持 `wagtailblog3/tests/` 全局集成测试与 `observability/tests/` 不动，修正了相对导入路径，使全库测试用例可被 `python manage.py test` 精准自动发现。

## 3. 多 Agent 协同与算力梯次路由 (原 24)

- **角色矩阵与职责**：确立主 Agent（技术负责人与编排者）统领 8 大专业子角色（`pm`、`arch`、`backend`、`frontend`、`qa`、`review`、`ops`、`data`），实现专人专责与单一写入者原则。
- **阶梯式算力调度**：
  - **`gpt-5.6-luna`**：快速低成本，负责日常只读检索、文档整理与小测试补充。
  - **`gpt-5.6-terra`**：平衡主力档，负责常规 Django/Wagtail 开发、组件优化与缺陷修复。
  - **`gpt-5.6-sol`**：前沿高能力档，专攻数据迁移、并发事务、ES 别名重构及生产上线高危判断。
- **对话指令协议**：标准化了 `/do`、`/plan`、`/implement`、`/review`、`/test` 及 `/confirm-production` 对话协议，规范了开发流程。

## 4. 多库异构灾备与恢复基线 (原 12)

针对 MySQL、MongoDB、MinIO 及 Elasticsearch 的异构特性，确立了标准化备份与恢复顺序：
1. **多介质备份清单**：
   - MySQL：`mysqldump` 逻辑快照。
   - MongoDB：`mongodump` 归档正文核心三大集合。
   - MinIO：媒体存储桶增量镜像同步。
   - Elasticsearch：快照存储（强制 `include_global_state=false` 防止破坏集群设置）。
2. **六阶段有序灾备恢复流程**：
   阻断外部写入（停应用/Nginx 503） $\rightarrow$ 恢复 MySQL $\rightarrow$ 恢复 MongoDB 与 MinIO $\rightarrow$ 校验或全量重建 ES 索引与别名 $\rightarrow$ 拓扑顺序拉起服务 $\rightarrow$ 端到端全功能验收。
3. **不可逾越红线**：严禁生产 `flush`，严禁删除 Mongo 正文，严禁带卷销毁 Docker，严禁通配符操作 ES 索引。
