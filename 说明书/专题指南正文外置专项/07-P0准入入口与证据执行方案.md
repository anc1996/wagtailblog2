## 历史方案原文（2026-10-05，非当前契约）

## 1. 目标与边界

本方案只解决三个前置问题：

1. 为未完成删除意图建立受控的取消/恢复入口设计。
2. 为 Page `711`、`715` 建立只读双库核验授权和证据方案。
3. 为后续隔离测试建立 L1 原始日志、环境和退出码证据规范。

本方案不执行数据库写入、不修复历史页面、不运行 Mongo GC、不绕过生命周期锁、不进入生产。

## 2. P0-A：取消删除意图入口

### 2.1 当前事实

- `cancel_pending_deletion_intent` 位于 `wagtailblog3/apps/external_content/deletion.py:620`。
- 允许取消 PENDING、过期 CLAIMED 和 FAILED；MYSQL_DELETED、COMPLETED 不允许取消。
- `locking.py:174-179` 对所有非 CANCELLED intent 冻结写入。
- 当前未发现 Wagtail 后台 URL、页面动作菜单、ModelAdmin、SnippetViewSet 或管理命令调用该取消函数。

### 2.2 推荐入口

采用**受权限保护的页面级后台动作**，不开放通用数据库管理：

- 入口位置：GuidePage 编辑页/状态页的“取消删除意图”动作。
- 入口前提：页面仍存在、当前用户具备该页面的编辑权限，并额外具备专项运维权限。
- 推荐权限名：`external_content.cancel_deletion_intent`。
- 动作参数：页面 ID、目标 intent ID、幂等请求 ID；禁止只传页面 ID 自动猜测 intent。
- 页面显示：展示 intent 状态、创建时间、`safe_gc_after`、操作者和不可变提示；不显示正文、Token、Cookie 或数据库凭据。
- 状态边界：仅 PENDING、过期 CLAIMED、FAILED 可取消；活动 CLAIMED、MYSQL_DELETED、COMPLETED 必须拒绝。
- 审计字段：actor、page_id、intent_id、旧状态、新状态、request_id、原因、时间、结果；日志不写正文和敏感信息。
- 并发语义：复用 `lock_page_lifecycle_hierarchy(..., check_write=False)`；重复请求必须幂等，不能缩短安全期或清理 Mongo 正文。

### 2.3 实现前必须补齐的测试

- 权限：无权限拒绝，具备页面权限但无专项权限拒绝，双权限允许。
- 状态：PENDING/过期 CLAIMED/FAILED 成功；活动 CLAIMED/MYSQL_DELETED/COMPLETED 失败。
- 并发：两个取消请求只产生一个有效状态转移。
- 安全：取消后允许正常编辑；不改变正文、Manifest、Mongo 版本或正式指针。
- 审计：成功、拒绝、异常均有结构化记录，且不包含敏感数据。

**准入条件**：以上契约完成独立审查后，才允许编写后台入口代码。

## 3. P0-B：711/715 只读双库核验

### 3.1 授权单

执行前必须明确记录：

- 目标环境：测试/副本环境名称，禁止生产；若为当前共享环境，必须明确只读连接。
- 目标页面：仅 `711`、`715`，禁止扩大范围。
- 数据库：MySQL 和 Mongo 的主机、端口、库名通过环境配置确认；禁止命令行明文密码。
- 操作：只允许 SELECT/find/count/聚合读取；禁止 save/update/delete/drop/flush/ensure_indexes。
- 产物：脱敏 JSON/Markdown 报告和退出码；不导出正文原文、凭据或完整敏感请求。
- 终止条件：环境不确定、连接指向生产、凭据来源不明、发现写操作、目标 ID 不匹配，立即停止。

### 3.2 最小核验字段

MySQL：page ID、specific model、live、live_revision_id、Revision ID、外置状态的 draft/approved/published revision pointer、Manifest 身份字段、intent 状态。

Mongo：page_id、field_name、version_id、model_label、generation、payload_sha256、created_at、deleted/tombstone 状态；只比较身份和哈希，不导出正文。

### 3.3 结论分类

- `MATCHED`：六键身份、哈希和指针完整匹配。
- `VERSION_MISSING`：MySQL Manifest 指向的 Mongo version 不存在。
- `HASH_MISMATCH`：版本存在但哈希不一致。
- `POINTER_MISMATCH`：Revision/page/field/generation 不一致。
- `UNKNOWN_ENVIRONMENT`：无法证明目标不是生产，报告不得继续。

711/715 不允许自动修复；只输出恢复方案候选和人工审批所需信息。

## 4. P0-C：L1 隔离测试证据

### 4.1 执行前

- 确认 WSL2/Conda 环境、专用 MySQL `13306`、Mongo `13307`、固定库名和环境凭据。
- 运行零网络/目标断言预检；保存环境指纹，不保存密码。
- 由执行人和复核人确认命令、目标、测试范围和输出目录。

### 4.2 执行中

每个测试批次单独输出到 `output/test-results/`，同时记录：命令、开始/结束时间、退出码、测试计数、失败摘要、服务目标、Git 工作树摘要。禁止 `--keepdb` 指向未知库，禁止自动清库和迁移。

### 4.3 L1 准出

只有原始日志可读、退出码可复核、环境目标匹配、测试计数可重放、失败已分类时，才可标记 L1。代理口述、聊天截图、无命令的“全绿”均保持 L0。

## 5. P0 执行顺序

1. 复核本方案并登记授权单模板。
2. 先完成取消删除意图入口的权限/状态/审计契约评审；不写代码。
3. 完成 711/715 只读目标确认；授权不足则保持阻断。
4. 通过环境预检后，执行一次只读完整性核验并保存证据。
5. 证据复核通过后，再单独决定是否进入取消入口实现和 L1 双库测试。

## 6. 明确禁止

- 不把取消入口做成任意 intent ID 的公开接口。
- 不因用户删除失败而自动将 intent 标记 CANCELLED。
- 不把其他页面正文指向 711/715。
- 不直接修改 Mongo、MySQL 指针或删除意图状态来“恢复可删”。
- 不把本方案当作已实现或已验收。
