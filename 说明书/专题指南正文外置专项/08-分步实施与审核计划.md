## 4. 后续实施与审核纪律

1. 先确认当前分支、工作树和基线；仅在批准写集内实施，保留继承改动。
2. 每批先编写失败注入并记录有效 RED，再最小修复取得 GREEN；characterization 与事后回放不得冒称实施前 RED。
3. L0 封套禁止真实 socket/数据库 IO，拒绝数据库测试类；不因代理或资料查询放宽隔离。
4. 对超时/COMMIT 未知先核对 SQL 权威状态，禁止自动重放；对账仅分类，不绑定指针、不修复、不物理删除。
5. 主代理处理复杂实现与最终判定，独立复核只读；简单独立写集可委派。角色按实际工具与本会话授权，不改长期配置或凭名称确认底层身份。
6. 每批需定向测试、guarded 系统检查、CSS、diff 与写集核验；静态门禁不替代业务或真实资源证据。
7. 门禁与审核通过后在功能分支作中文 Conventional Commits 本地原子提交；禁止 push、擅自合流 main、触碰生产。
8. 回滚仅撤回该批差异，不覆盖整个继承文件或清理无关未跟踪文件；无跨库裸 delete 补偿。

### 6.1 R3-E 两阶段矩阵冻结（2026-10-10）

真实环境验收分为两阶段，第一阶段作为本轮核心准出范围，第二阶段仅在
系统能力和异步依赖满足时执行。每条流程使用独立
`r3e_flow_<字母>_<时间戳>` 前缀，流程之间不复用页面、Revision、Token
或 Alias；结束后核验 MySQL 页面/Revision/external state、Mongo 正文六维
身份/hash/指针、Redis 防重状态与 TTL，以及本轮 Mongo 物理删除计数。

**第一阶段（核心必测）**：Flow A 纯草稿生命周期；Flow B 发布、草稿双
版本共存与下架；Flow C Copy/Alias 引用及隔离；Flow D 短时防重与自动/
手动并发拦截（ID-01～06）；Flow E 已发布文章删除与 DeletionIntent；
Flow F 字段独立性与正文保真；Flow G Revision 历史版本与回滚安全；
Flow H 权限、身份与 Token 参数绑定；Flow I 网络中断、响应丢失与
unknown/待核对处理；Flow J 跨存储失败与事务补偿边界。

**第二阶段（条件依赖与异步阻断）**：Flow K 树层级、子页面、移动与级联
删除；Flow L Locale 翻译、翻译父链与独立删除；Flow M Workflow、预览、
审批、指定 Revision 与排期发布。若当前后台未接入对应能力，必须记为
N/A/未接入，不得冒充通过。X-3 中真实 Elasticsearch 异步投影、消费者
延迟/乱序/恢复列为后续阶段阻断项。

**横切守卫**：X-1 浏览器刷新/后退前进/双标签/重复提交；X-2
processing、succeeded、failed、unknown、TTL 超时、结果缓存缺失与 Token
过期；X-4 测试环境隔离与逐流三库对账。任一场景无法由真实 browser-skill
安全注入时，记录为 BLOCKED/未验，不以 L0、DOM 模拟或 ORM 造数替代。
Worker、Beat、GC 保持关闭；证据统一写入
`output/d3-implementation/r3e-real-validation/` 与
`output/playwright/r3e/`，本节不记录终端流水账。
