## 历史交接方案原文（2026-10-05，非当前执行任务）

## 1. 目的

为历史 Page `711`、`715` 提供可复核、非生产实时、最小范围的 MySQL/Mongo 配对数据，使专项能够判断正式指针、Mongo `version_id`、六键身份和 SHA-256 是否一致。

## 2. 首选来源

优先级从高到低：

1. 由数据库负责人从**非生产实时库**提供的时间点一致只读副本。
2. 由数据库负责人从备份恢复出的临时只读实例，并提供来源时间点。
3. 配对的脱敏 JSON/JSONL 导出文件，分别覆盖 MySQL 元数据和 Mongo 版本元数据。

禁止直接连接生产实时 MySQL/Mongo。当前 `test_g4_external_content` 虽有 109 张表，但没有 711/715，不能作为历史数据来源。

## 3. 最小数据范围

### MySQL

仅导出 `page_id IN (711,715)` 及其必要关联记录：

- `wagtailcore_page`：id、content_type、live、live_revision_id、path、depth、first_published_at、last_published_at。
- 对应 Revision：id、object_id、base_content_type、created_at、approved、live_revision 相关状态；不导出完整 `content_json`。
- `external_content_publication_state`：page_id、model_label、draft/approved/published revision id、三份 Manifest、publication_generation、source_page_id、source_revision_id。
- `external_content_deletion_intent`：intent id、page_id、status、safe_gc_after、generation、收集/失败计数、时间；不导出正文和敏感操作者信息。

### MongoDB

仅导出 `external_content_versions` 中：

- `page_id IN (711,715)`；以及 MySQL Manifest/删除意图明确引用的 `version_id`。
- 保留 `model_label`、`page_id`、`field_name`、`codec`、`schema_version`、`version_id`、`payload_sha256`、generation、created_at、删除/墓碑状态。
- 默认排除 `payload` 正文；若确需验证内容重算哈希，必须另行书面授权，并把正文放在受控临时副本中，不进入日志和文档。

## 4. 提供方必须交付的元数据

- 来源类型：备份恢复/只读副本/脱敏导出。
- 来源环境名称：必须明确“非生产实时库”。
- 数据时间点和时区。
- MySQL 与 Mongo 是否同一时间点或如何建立配对关系。
- 导出范围证明：只包含页面 `711`、`715` 及必要引用。
- 每个文件的 SHA-256 校验值。
- 导出工具版本和命令摘要；命令中不得包含密码、Token 或 Cookie。
- 只读账号或文件交接权限；不交付生产写权限。

## 5. 接收与核验流程

1. 先接收清单和 SHA-256，不先打开正文文件。
2. 核对来源声明、时间点、范围和校验值；任一缺失即停止。
3. 在隔离工作区校验文件哈希和格式；不复制到生产路径。
4. 先做元数据比对：MySQL Manifest → Mongo `version_id` → 六键身份 → `payload_sha256`。
5. 生成 `MATCHED`、`VERSION_MISSING`、`HASH_MISMATCH`、`POINTER_MISMATCH` 或 `SOURCE_UNVERIFIED` 结果。
6. 由第二人复核结果和原始证据；只写报告，不改源数据。
7. 按交接规则销毁临时副本；保留脱敏结果和校验清单。

## 6. 停止条件

- 来源无法证明不是生产实时库。
- 只有 MySQL 或只有 Mongo，无法配对。
- 页面范围扩大到 711/715 之外。
- 导出包含密码、Token、Cookie、私钥或不必要正文。
- 校验和不一致、时间点不明、文件被修改。
- 需要写入、迁移、恢复、GC 或改变指针才能继续。

- [ ] 确认范围仅为 `711`、`715` 及必要引用。
- [ ] 已提供文件 SHA-256 校验值。
