# 专题指南正文外置实现方案

> 版本：v1.0 (最终收敛交付版)\
> 适用范围：Wagtail 8.0 / Django 5.2.8 / MySQL 8.4 / MongoDB 4.11 / Redis 5.2 / Elasticsearch 8.19\
> 核心模块：`wagtailblog3.apps.external_content` 与 `wagtailblog3.apps.guides`

---

## 1. 架构总览与核心设计原则

### 1.1 方案背景与痛点
传统 Wagtail `Page` 模型正文（如 `StreamField`）默认序列化后存储于 MySQL 的单个长文本字段中。当长篇文档、专题指南正文或高频版本演变发生时，MySQL 面临行溢出、主从同步延迟高、备份开销大以及 JSON 反序列化内存膨胀等问题。
本方案将专题指南（`GuidePage`）及未来扩展页面的超大富文本正文外置于 MongoDB 文档存储，而在 MySQL 中仅保留结构元数据、树形拓扑（Treebeard）、发布状态指示与轻量级版本清册（Manifest），实现关系型存储与文档型存储的高性能解耦。

### 1.2 存储分层与权威数据源契约
系统严格划分双库权威边界，杜绝数据多头写入与状态不一致：

| 领域 / 数据资产 | 权威存储源 | 说明与生命周期 |
|---|---|---|
| **页面骨架与元数据** | MySQL (`wagtailcore_page` 等) | 树路径 (`path`)、深度 (`depth`)、URL 别名 (`slug`)、标题 (`title`)、所有者、Locale 多语言等。 |
| **版本草稿清册** | MySQL (`wagtailcore_revision`) | Revision 的 `content` JSON 仅保留外置字段的占位引用与版本指针 (Manifest)。 |
| **正式发布快照状态** | MySQL (`ExternalContentPublicationState`) | 记录当前 live 页面对应的正式 `published_manifest`、发布时间戳与代际号 (`generation`)。 |
| **正文版本载荷** | MongoDB (`external_content_versions`) | 不可变文档，按 `(page_id, field_name, version_hash)` 建立唯一不可变版本，只追加、不就地修改。 |
| **全文检索可见视图** | Elasticsearch (`content_search_v2`) | 由正式发布快照投影生成的只读全文检索文档，支撑多模型统一检索。 |

## 2. 核心数据契约与接口规范

### 2.1 ExternalContentPageMixin 与模型声明
业务页面模型（如 `GuidePage`）只需混入 `ExternalContentPageMixin`，并通过类属性 `content_storage` 声明哪些字段需外置：

```python
from wagtail.models import Page
from wagtail.fields import StreamField
from wagtailblog3.apps.external_content.mixins import ExternalContentPageMixin

class GuidePage(ExternalContentPageMixin, Page):
    # content_storage 声明需要外置到 MongoDB 的字段名称与编解码器配置
    content_storage = {
        'body': {'codec': 'streamfield', 'collection': 'external_content_versions'}
    }

    body = StreamField([...], use_json_field=True)
    # 其他 MySQL 存储的原生字段...
```

### 2.2 字段运行时状态机 (Field Lifecycle State)
为了避免无谓的网络 IO 与内存占用，外置字段在页面生命周期中具有四种明确状态：
1. **UNLOADED（未加载）**：ORM 从 MySQL 实例化 Page 时，外置字段仅持有轻量级指针，不主动拉取 Mongo 数据。
2. **LOADED（已加载）**：首次访问外置字段值时，协调器根据当前页面的来源上下文（Live 或指定 Revision）按需从 Mongo 载入并反序列化。
3. **DIRTY（已修改）**：管理后台提交表单或业务代码修改了该字段，记录最新内存对象并标记脏状态，用于后续生成新版本。
4. **CLEARED（已清空）**：页面被显式置空，作为合法的空内容版本保存。

### 2.3 MongoDB 集合规范与复合索引
正文外置版本存储于 `external_content_versions` 集合，具备严格的唯一性约束与时间戳审计：

- **主业务字段**：
  - `page_id` (int): Wagtail Page 主键 ID；
  - `field_name` (str): 外置字段名称（如 `body`）；
  - `version_hash` (str): 字段序列化后的规范 SHA-256 哈希值；
  - `payload` (bson/dict): 序列化后的实际正文载荷；
  - `created_at` (datetime): 版本创建时间。
- **强制复合唯一索引**：
  `CREATE UNIQUE INDEX uidx_page_field_hash ON external_content_versions (page_id, field_name, version_hash)`

## 3. 跨存储事务一致性与失败安全回滚 (Rollback Matrix)

### 3.1 双库一致性基本原则
MySQL 与 MongoDB 之间不存在分布式两阶段提交（2PC）。本方案采用**“Mongo 预备层写入不可变版本 -> SQL 事务提交引用与状态 -> 发生异常 SQL 事务回滚”**的非阻塞一致性模型：
1. **先 Mongo、后 MySQL**：先将不可变正文版本安全落盘至 MongoDB，再在 MySQL 开启显式事务写入 Revision 及 Manifest 引用；
2. **失败安全与只读孤儿允许**：若 SQL 事务因唯一键冲突、死锁或网络异常而失败回滚，**严禁在异常处理路径中调用 Mongo delete 物理删除**已写入的正文版本（防止网络抖动导致的误删与级联灾难）。Mongo 预备版本允许暂时作为孤儿存在，后续由只读对账机制监控；
3. **轻量请求防重**：同一用户短时间内快速重复提交时，通过客户端标记与短期 Redis 锁实现防重，返回友好提示。

### 3.2 页面生命周期动作适配 (Wagtail Actions)

- **首次创建 (First Creation)**：
  在 Page 尚未持久化到 MySQL、尚无正式 PK 前，使用内存分配机制计算正文规范哈希；当 SQL `add_child` 获得真实 `page_id` 时关联写入，确保不会因提前伪造 ID 污染数据。
- **保存修订草稿 (Save Revision)**：
  计算修改字段的 SHA-256，幂等写入 Mongo 版本；在 `wagtailcore_revision.content` 中写入包含该 version_hash 的 Manifest，不阻塞正常页面保存。
- **正式发布 (Publish)**：
  在同一 MySQL 事务中更新 `ExternalContentPublicationState` 的 `published_manifest`，标记 live 快照版本，并向搜索 Outbox 表插入投影变更事件。
- **页面复制与别名 (Copy & Alias)**：
  - **Copy（深拷贝）**：为新 Page 实体复制当前正式发布的版本引用，在 Mongo 中写入对应新 `page_id` 的版本映射，完全保留数据独立性。
  - **Alias（别名页）**：仅引用源页面，不重复消耗 Mongo 存储空间。
- **下架与删除 (Unpublish & Delete)**：
  - **下架**：仅更新 MySQL 的 `live=False` 标志与发布快照状态，Mongo 历史版本完整保留用于版本追溯与撤销恢复。
  - **删除**：采用软删除/删除意图机制，严禁物理级联硬删除 MongoDB 正文集合，防范误操作导致不可逆丢失。

## 4. 全文检索接入与投影机制 (Search Projection)

### 4.1 统一受管内容索引架构
为了使 `GuidePage` 与传统 `BlogPage` 共同无缝支持全文搜索，系统构建了统一投影适配层（`apps.search`）：
1. **发布快照驱动**：仅已正式发布的正文版本允许投影至 Elasticsearch，草稿版本与历史废弃版本严格屏蔽在索引之外；
2. **Outbox 事件投递**：页面发布/下架时，通过 MySQL 事务内写入 Outbox 事件表，由 Celery 异步 Worker 安全消费并推送至 ES，解耦主站前台请求；
3. **内容聚合与高亮**：搜索适配器将外置 StreamField 纯文本提取与正文标签聚合为 ES 的统一 `body_text` 字段，支持中文分词与摘要高亮渲染。

## 5. 环境配置、启动与运维指引

### 5.1 服务与端口标准
- **开发与测试服务器标准启动命令**：
  ```bash
  python manage.py runserver 0.0.0.0:8080
  ```
- **配置架构收敛**：
  全面废弃独立的 `external_content_web.py` 与 `external_content_test.py`。开发环境统一载入 `wagtailblog3.settings.dev`（继承 `base.py` 与 `database.py`），通过环境变量 `DJANGO_SETTINGS_MODULE=wagtailblog3.settings.dev` 标准化运行。

### 5.2 数据库连接与权限隔离
- **MySQL 测试数据库**：`wagtailsoftblog_test`（只读/读写测试，生产库 `wagtailblog` 严禁连接）；
- **MongoDB 测试数据库**：`wagtailblog_test`，核心业务集合为：
  - `blog_content`
  - `blog_page_revision_bodies`
  - `content_body_versions`
  - `external_content_versions`
- **严禁事项**：
  - 严禁在生产或开发环境执行任何形式的 `DROP DATABASE`；
  - 严禁在无明确授权下物理清理 `external_content_versions` 中的业务数据。
